# 项目记录、证据关系与检查失效

用于长稿、多轮返修、多来源研究和从实验直接成文。短任务只记录会影响下一步的决定、依据和未解问题；单句润色无需建库。沿用项目已有工作记录，不同时维护几套互不一致的“最终事实”。可从 [轻量项目记录](../templates/project-record.md) 开始，需要机器检查时使用 [JSON 空模板](../templates/evidence-ledger.json)。记录存研究项目，不能写进安装的技能目录。

## 一份记录连接不同成果

采用稳定 ID 连接研究问题、来源、运行、分析、图表、主张、问题和用户决定；显示编号、页码和投稿引文序号另行映射。记录对象随任务选择，不要求每句建档。

| 对象 | 最小有用信息 | 特别注意 |
|---|---|---|
| 来源 `sources` | ID、真实定位/URL、实际版本、已读范围；有本地文件时关联其 ID | 题录、摘要、局部正文、全文可用是不同状态；全文可用仍不支持任意主张 |
| 文件 `artifacts` | ID、类型、项目相对路径、SHA-256、字节数、上游输入 ID 与当时指纹 | 数据、脚本、配置、运行日志、分析表、图、稿件分别登记；登记不是执行 |
| 主张 `claims` | ID、具体句意、支持状态、证据位置及实际复核时的版本/指纹、正文/图表使用位置 | 复合判断分别核证；数值归属、分母、条件和反例不能只靠 hash 判断 |
| 问题 `issues` | ID、原句与定位、受影响主张、影响级别、当前状态、解决依据 | 已解决、未解决、回归和暂缓分开；新增意见注明新证据或原先漏查，避免无理由换标准 |
| 决定 `decisions` | ID、用户已经决定的范围/工具/输出、时间、对应信息位置 | 继续使用已给授权，不每轮重问；假定的偏好与明确决定分别写 |
| 检查 `checks` | ID、方法、日期、范围、输入指纹、实际结果及回执位置 | 结构检查、语义复核、数值复算、视觉检查分别记录；未运行明确标记 |

支持状态沿用 [诚信与证据](integrity-and-evidence.md) 的 `supported/qualified/disputed/unverified/todo`。另记性质是观察、计算、解释还是假设。`read_scope` 记录 `metadata/abstract/excerpt/full/unread`；“访问受限”“未读”“读后不支持”“相互冲突”不能混为“假文献”。

核心引用保留能够定位论断的短摘录及上下文信息，不缓存无必要的整篇版权文本。反向检查审阅报告引用的“原句”是否真的位于当前版本；同词出现不等于定位正确。恢复时先核文件身份、已读范围和用户决定，再继续未完成部分。

## 变化怎样传递

示例关系是 `原始数据 + 分析脚本 + 参数 → 汇总表 → 图 → 结果句 → 摘要`。框图可以来自设计/RTL/接口说明，无需虚构数值数据源。为输出记录生成时使用的上游指纹；检查记录输入的当时指纹；每条主张的证据项冻结实际复核时的来源身份。任何上游改变，受影响的下游产物、旧主张与旧验收需要重新核查；重新登记源文件不能自动让它们恢复有效。

能重建的表图应在新位置实际重建并验证，再登记新依赖。语言编辑影响范围时，同步引用该结论的摘要、题注和投稿材料。理论证明、定性材料或外部文献同样记录实际版本与支持位置，但不伪装成已跑计算实验。

长期项目可使用 JSON 检查下面的关系；轻量 Markdown 由助手按相同规则维护。保留工作检查点不等于稿件已通过。项目本已有 Git 时可按合理里程碑保存；不为每个随机种子提交、不默认推送、不安装宿主全局 hooks。外部模型复核与持续监测见 [可选工作流](optional-workflows.md)。

## 标准库助手

[research_ledger.py](../scripts/research_ledger.py) 在 Windows/Linux 使用同一接口；`python` 换成实际解释器，`<技能目录>` 换成已加载路径。默认记录文件为研究根目录的 `.thesisforge/research.json`，可用 `--ledger` 指定根目录内其他位置。

```text
python -B <技能目录>/scripts/research_ledger.py --root . init
python -B <技能目录>/scripts/research_ledger.py --root . record-file --id DATA-1 --path data/raw.csv --kind data
python -B <技能目录>/scripts/research_ledger.py --root . record-file --id CODE-1 --path analysis.py --kind code
python -B <技能目录>/scripts/research_ledger.py --root . record-file --id TABLE-1 --path results/summary.csv --kind table --input DATA-1 --input CODE-1
python -B <技能目录>/scripts/research_ledger.py --root . check --strict
```

`record-file` 只给实际存在文件取指纹，不运行代码。`--input` 只能关联当前有效的登记文件；更新文件时省略 `--input` 会保留原输入快照，不能用省略参数清除过期关系。工具采用项目内路径、单写者锁和原子替换记录；异常退出留下锁时先查该写者和记录，不自动删除锁抢占工作。

每个 `claims[].evidence[]` 项只关联一个非空的 `artifact_id` 或 `source_id`，并包含实际支持位置 `locator`。还须保存以下冻结字段，不能只指向一个可不断更新的 ID：

| 证据类型 | 冻结字段 | 检查行为 |
|---|---|---|
| 直接关联文件 `artifact_id` | `observed_sha256`：实际复核文件的 64 位 SHA-256 | 对比当前登记指纹，同时核查文件和上游输入是否仍有效 |
| 外部来源 `source_id` | `observed_locator` 与 `observed_version`：实际复核时 `sources[].locator/version` 的非空字符串值 | 对比实际来源地址和版本，不能把另一篇来源沿用相同版本号而刷新旧主张；工具不联网判断网站是否已更新 |
| 关联本地文件的来源 `source_id`，且来源含 `artifact_id` | 同时保存 `observed_locator`、`observed_version` 和 `observed_sha256` | 来源、版本和本地文件身份分别检查；只更新版本文字或重新登记文件不能刷新旧主张 |

缺少或无效的冻结字段得到 `unverified`，不会自动拿当前文件补填；冻结身份与当前登记身份不符或依赖失效得到 `stale`。一条主张有多个证据项时，只要有任一失效项，整体仍为 `stale`，其他缺信息项不能把它覆盖成 `unverified`。报告保留原始 `declared` 状态，并另给 `effective` 状态；记录相容也不会把 `todo/disputed/unverified` 自动升为支持。

旧记录缺这些字段时，先找到当时实际阅读或分析的版本，不能从现文件批量复制指纹来消除提示。确实重读或重算后再按事实修订主张、证据位置和冻结字段；没有当时版本或无法复核的保持未核实。来源版本应能区分真正不同的修订或取证快照；只凭一个长期不变的名称不能跟踪网页内容变化。

主张已冻结本地文件的 `observed_sha256` 时，删除来源的 `artifact_id` 关联不会恢复支持状态，而是留下无法核对该哈希的待核项。应恢复实际来源文件的绑定或在重新核查后记录新的证据，不能只删字段消除失效提示。

`read_scope=unread` 不能支持已核实主张，包括题录身份。实际读过的 `metadata` 可用于 `kind=bibliographic` 的身份主张，但不能支撑科学内容；这些范围仍是记录的阅读声明，不是工具替作者完成了阅读。

`check` 只读，报告缺文件、循环依赖、过期输入、缺证据位置/冻结身份、失效验收等。其 `coverage` 分母是**已经登记的主张**，没有枚举整稿，语义核实数始终为 0。`consistent_within_coverage` 仅表示检查覆盖内的记录相容，不能称论文事实全部正确。普通模式完成扫描返回 0；`--strict` 对记录问题或空库返回 1；输入/配置/读写错误返回 2。`checks` 中的执行状态是使用者据实际工作填入的回执，不是该工具重新执行得到的证明。

## 有界局部修改

修改长稿时先明确目标自然段/小节，周边作为理解材料。需要确定性应用修改可准备 UTF-8 JSON：

```json
{"replacements": [{"old": "要替换的唯一完整片段", "new": "已经核准的改文"}]}
```

```text
python -B <技能目录>/scripts/research_ledger.py --root . apply-patch --file draft.tex --expected-sha256 <准备改文时的SHA256> --plan patch.json --output revised.tex
```

每个旧片段在原稿必须唯一（重叠出现也计为多处），各替换范围互不重叠；原稿指纹不符就重新对照，不强行套补丁。输出必须是新文件，保留原稿、未改区域、BOM 和原行尾，不可用于 DOCX 字节拼接。新文件写入失败会清理本次创建的残片，但读者不应在命令结束前读取它。工具不判断修订是否保真；应用后仍运行 [字面量检查](../scripts/check_literals.py) 并回读数据归属、公式含义、条件与引用关系。

## 记录怎样保持轻量

只展示用户需要的正文、重要变化与未解事项，完整工作记录不必印入论文。来源未查、分析尚未完成时可以明确工作稿标记或关联缺口表；不能让干净排版制造“已完成”假象。没有重大新发现的复审不添加空表或重复免责声明。最终验收引用真实交付文件身份，不引用曾经通过的中间版。
