# 写作与润色

目标是准确、具体、可读，让有背景的读者顺着问题和证据形成判断。新写和改写均采用专业、自然、非口语化的学术书面语。减少空泛或“套话感”靠修好论证与信息，不靠禁词表、统一短句或故意加入口头禅。与 [自然写作与文稿终检](natural-writing-and-review.md) 配合：该文规定各模式的编辑边界、六类意见、保真核对与最终版本终检，本节保留中英文和学校/刊物体例细则。

编辑已有稿件时，先确定本次允许改动的内容。仅润色时，用原材料澄清表达，保持原有数据、比较基线、例外条件和结论强度。发现事实冲突或缺少推导时另列具体位置与依据。受托实质修订时可核实并修正，在本次范围内复查受影响的主张。

主张强度的逻辑规则见 [论证与逻辑](argument-and-logic.md)。本节补充中英文表述分档、人称与摘要写法。来源是已获取的 [GB/T 6447—2025](gbt-6447-2025.md)、[CY/T 173—2019](cyt-173-2019.md)、学校手册、学报指南，以及关于 Zobel《Writing for Computer Science》的大学课堂讲义转述（只用讲义，不从盗版全书摘引）。不依据尚未取得全文的陈浩元 / cjstp 专论来写立场。

## 编辑顺序

1. 核对事实、引用、单位、基线和断言强度（用主张三档），固定数字归属、上下界、否定范围、条件、公式和引文等不能随润色改变的内容。
2. 补齐影响理解的对象、动作、条件和因果环节。
3. 调整章节与段落顺序，合并重复，补上回指。
4. 删除无信息增量的措辞，统一术语和符号。
5. 对最终版本独立通读，按 [终检流程](natural-writing-and-review.md#最终版本的独立终检) 双向对照原材料与成稿；包括原样保留的内容、图表说明和中英对应部分。局部任务按指定范围执行。

## 让名词、动作和条件承载信息

- 重要名词指向明确对象，动词说明操作，结果写成可理解的状态或变化。
- 术语、指标名、符号全文统一。不要用近义词制造不存在的技术差别；不要把带宽与吞吐、精度与准确率、仿真与实测混用。
- 缩写按受众需要在首次出现时给出全称，之后只保留一种写法。
- “这使得、由此、其性能”如果可能指向多个对象，就写回名称。
- “赋能、闭环、协同、底座、生态、突破、首次、高效”等词：若是领域里有定义的概念，定义后可用；若只是挡住了真正的操作或约束，就改写成关系；若删掉也不损失事实，就删除。不要机械替换成另一组口号。

## 中文表述分档（够用与过度）

**摘要与结论各自回答什么。** 实证学位论文的摘要交代研究目的、方法、结果和结论，重点写结果与结论。期刊稿按稿型和投稿要求取舍，综述可突出覆盖范围与综合判断。结论章回答总体研究问题，说明证据支持的贡献、适用条件、局限与后续工作。比较结果已在摘要交代时，结论可解释其对工程选择的意义。[文献摘要编写规则](gbt-6447-2025.md) · [学位论文摘要与结论](gbt-7713.1-2025.md)

**过度：** 没有可核验依据却写「首次提出 / 填补国内空白 / 达到国际领先 / 完美解决」；对已经测到的结果再叠「可能、也许、似乎、在一定程度上」；或者反过来，删光范围限定，把局部结果写成普遍成立。计算机学报、电子学报、软件学报要求摘要体现或突出创新，但已获取的指南并不要求作者写「首次 / 填补空白 / 国际领先」。

**第一人称，以学校或刊物为准。** GB/T 6447—2025 6.1 允许作者自撰摘要使用「本文 / 我们 / 笔者」，二次文献摘要应使用第三人称。已打开的北京大学 2018/2019 写作指南全文无「第一人称 / 第三人称 / 人称」；2.3 避免的是「第一章……；第二章……」式提纲，不是人称禁令。不得把「摘要不用第一人称」写在该指南名下，也不得用该指南收窄 6447 的许可。该校 2014 年 4 月《研究生论文答辩和学位申请指南》印刷页 38 写「不得用『我们』等群体性称谓，一般用『本文』『研究表明』等科学用语」，只约束该校流程，允许「本文」，不能改写成「摘要不用第一人称」，也不得用它收窄 6447 对「本文」的许可。《通信学报》要求摘要避免「本文」「作者」。清华大学 2025-03 指南全文未见第一人称禁令，**不得用它收窄** 6447 的许可。写成哪一份文件，就服从那一份叠加规则，不要把国标许可变成对通信学报稿或北大答辩形式审查的许可，也不要把校规禁令写成全国禁令。

## 英文表述分档（够用与过度）

依据关于 Zobel 类计算机科学写作建议的课堂讲义转述，以及已确立的 IEEE/ACM 贡献前置习惯，不是从盗版全书摘句，也不发明「每段最多几处限定语」的数字规则。

**够用：** 尽早、具体地写出贡献，多用精确动词和可测量结果；按实际做了什么来报告（数据、假设、失败了什么）；在结果旁交代影响该比较的条件，把跨结果的外推限制集中在 limitations / threats 中；评价部分需要时给出置信区间或多种子变异。

**过度：** 装饰性叠套限定（may perhaps suggest the possibility that）；未挣得的 novel / robust / efficient / first / best；或者反过来，主张跑出证据（把仿真说成测量，把测试集数字说成普遍性能）。「首次 / 最优」必须带范围（在何种协议下、相对哪些基线、文献截止于何时）。

## 中文学位论文与英文论文的文体切换

- **中文学位论文：** 许多学院（如武汉大学计算机学院写作规范）要求正文避免「我/我们」；摘要人称按上一节的学校/刊规切换，「本文」可否使用不是全国统一。这是约束层，以用户学校或目标刊物为准。
- **英文论文或英文学位论文：** 系统与应用领域常见包容性的 we，以及用 this paper/this thesis 指文档本身；Nature 教育类建议用过去时陈述研究任务、用现在时陈述论文文本。不要把中文校规里的“禁止第一人称”自动套到英文稿，也不要把英文的 we 自动套到禁止第一人称的中文摘要。
- 中文学位论文把 this paper 译成「这篇论文」不准确，应区分「本论文 / This thesis」与期刊「本文 / This paper」。
- 语气保持客观。慎用「首次提出、最先进、高效」；有十分充足的证据再用。

## 段落与句子

- 可先写判断，再写细节；时间顺序或方法过程清楚时沿用其组织方式。不要每段都写成「总述一句、列三点、总结一句」。
- 同级列表只用同一个分类维度。
- 句长服从概念边界：复杂关系允许长句；主语漂移或条件互相遮蔽时再拆。不要把所有句子砍成一样长来“像人写”。
- 删掉主持写作过程的空话：「下面深入分析」「由此可见意义重大」「综上所述非常重要」。章节定位如果真能帮助阅读，可以保留。
- 图表在正文中按编号引用，并解释读者该看出什么，不要只写「如图所示」。

## 摘要、引言、结论的写法差异

- 摘要独立完整，突出结果与结论，少写背景，不堆引用，不出现正文没有的信息；不加评论，不重复题名，不复制正文。字数与关键词个数：学位论文先看 [学校叠加层](school-overlays.md) 与 GB/T 7713.1—2025 5.2.9，不要用 6447 的「约 400 / 300 / 150 字」覆盖学位论文窗口；期刊看 [journals-cn.md](journals-cn.md)、[venues-acm-elsevier.md](venues-acm-elsevier.md) 或目标刊物指南。关键词选词见 [cyt-173-2019.md](cyt-173-2019.md) 与 [keywords-checklist.md](../templates/keywords-checklist.md)。
- 引言进入问题、缺口和贡献，不要重复摘要全文。英文引言把贡献前置、写具体。
- 结论给总结论、条件、意义与后续问题，不把创新点口号原样粘贴充数，也不引入新数据。

## 人称、时态与公式文字

- 公式、符号的正斜体和含义全文一致；定义过却从未使用的公式应删或真正用上。
- 中英文标点、单位和数字写法分别遵守学校模板、GB/T 相关规定或 [IEEE 体例](ieee-style.md)，不在未读手册时发明细则。

## 润色时禁止做的事

- 为去套话而改写直接引语后仍加引号
- 为了“更有人味”编造实验经历、对话或评审反馈
- 把限定条件当作冗余删除，导致主张变强
- 用同义反复把一段话拉长而不增加信息
