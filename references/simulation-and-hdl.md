# 仿真、数字逻辑与 HDL 实验

先写下研究对象的可观测输入、状态更新规则、输出和时钟单位，再选工具。将可手算的样例、正式工作负载和故障复现输入分别保存。运行所用的模型层次要和正文主张一致。

涉及连续时间方程、空间网格或数值积分时，先按[实验设计](experiment-design.md)核对解析参照、步长或网格细化所改变的误差。

## NoC 与离散事件仿真

- 明确仿真单位是包还是 flit，每步能做哪些注入、排队、仲裁、传输和送达操作。记录网格/拓扑、路由、链路容量与延时、包长、缓冲及反压模型。软件模型省略虚通道或信用流控时，说明这会限制哪些网络负载或硬件结论。
- 选择与主张相称的配置。有限批任务可从释放开始直至全部送达，报告完成周期、按包时延及搜索成本。研究稳态吞吐时定义预热、测量窗口与停止注入后的排空策略，分别报告给定流量、实际注入率、交付率、积压和丢弃。记录分母是周期、节点还是节点周期。饱和附近的持续积压或超时本身是结果。
- 比较调度策略时固定任务释放及源/目的轨迹；策略改变实际注入时机是实验处理的一部分。时延起点选“释放”还是“注入”会直接影响结论。拥塞提前移到源端时，网络内时延下降可能同时伴随应用等待增加。保留二者或解释选择。
- 用单包无争用的跳数和时延、两包抢同链路、已知最优小图验证实现。按包 ID 核对生成、源端待发、在途、送达及丢弃的守恒，排空结束再核重复或遗漏。用解析例、参考仿真器或匹配轨迹交叉验证与主张相关的现象。随机合成流量和真实应用 trace 分列。
- 使用 gem5 Garnet 等后端时，先读本地 checkout 的构建目标、示例脚本和 `--help`，记录 commit、流量生成器、网络及包长设置。Garnet 官方示例用逐节点逐周期的随机试验生成包，包长随虚拟网络而变。只复用与本实验定义匹配的指标。[Garnet synthetic traffic](https://www.gem5.org/documentation/general_docs/debugging_and_testing/directed_testers/garnet_synthetic_traffic/)

## 从接口规格到可检查的 RTL

1. 将设计约束写成端口、位宽、复位极性和时序、握手成立的边沿、状态更新条件与可观测延迟。再实现可综合 DUT，单独写测试台。根据设计选择检查，如 FIFO 的满空和回绕、仲裁器的互斥/公平、流水线停顿与恢复。明确合法输入或环境假设。
2. 先用定向向量覆盖复位、空闲、并发、边界、背压和恢复，再按固定种子生成有约束的随机向量。用不同写法的参考模型逐事务比对，错误输出首个失败周期、输入、预期及实得值并以非零状态结束。加入看门狗，检查确实发生了足够的有效事务，保存失败种子及关键窗口波形。定向用例通过的范围应按已覆盖场景表述。
3. 选择可用后端。SystemVerilog 例子可在独立运行目录执行以下两步，顶层和文件名按实际工程调整。需要四态模拟时确认后端语义。VHDL 则按项目标准用 GHDL 分析、展开并运行测试台，核对断言级别。cocotb 测试要区分边沿握手值与边沿后更新的寄存器，按接口契约驱动，在信号稳定的阶段读取输出。[Icarus 选项](https://steveicarus.github.io/iverilog/usage/command_line_flags.html) · [VVP](https://steveicarus.github.io/iverilog/targets/tgt-vvp.html) · [cocotb 时序模型](https://docs.cocotb.org/en/stable/timing_model.html)

   ```text
   iverilog -g2012 -s tb -o sim.vvp dut.sv tb.sv
   vvp sim.vvp
   ```

4. 编译、功能仿真、综合、静态时序分析、上板或芯片实测分别登记。功能正确性写为已执行测试中的断言与覆盖结果。面积、最高频率、功耗等需要相应工艺库/目标器件、时钟及约束、工具报告和估计条件。若只有算法仿真或 RTL 功能仿真，正文只报告该层次的证据。

### 把算法或接口规格落实到可比的输出

从算法实现转为数字逻辑时，为每个被比较的量说明位宽、符号、舍入或饱和规则，以及结果应在哪个时钟边沿有效。对有停顿的流水线，参考模型按**实际接受的事务**推进，给输入分配标识，在输出握手时按规格核对次序与载荷。对定点算法，可先用独立的位精确参考实现定位 RTL 错误，再比较该参考实现与高精度算法之间的量化偏差。若结论涉及吞吐或时延，分别记录启动填充、连续服务和下游停顿所占周期。

### 参数化 FIFO 的实验设计

先约定空队是否直通、满队遇读写同拍是否接受新值、复位时在队数据怎样处理。这些是具体实现的契约。例如，设计采单时钟、空队无直通、满队同拍可替换队首，且每个被阻塞的有效载荷保持到握手。此时在有效沿之前采样两端握手；满队替换要先取旧队首，再将新值加入软件队列。每个阻塞周期也核对队首数据是否保持。复位清除占用时，逐段核对“入队数 = 出队数 + 复位清除数 + 当前占用”。[LaForest 的 ready/valid 握手与同步状态说明](https://www.fpgacpu.ca/fpga/handshake.html)

根据支持的配置选择能区分错误的参数。对宣称支持任意正深度的环形 FIFO，可测试深度 1、非二次幂及二次幂，重复填满、阻塞、同拍读写和排空。地址位宽足以表示深度，并不保证指针会在最后一个合法地址回绕。运行摘要按配置记录已核对的周期、事务、满队阻塞/替换次数、占用状态下复位等命中数；一项应覆盖的事件为零时补充定向激励。若接口约定满队必须等下一拍再写，就用相应的预期值检查该气泡。

例如 Icarus 可用 `iverilog -g2012 -s tb -Ptb.DEPTH=3 -o fifo3.vvp fifo.sv tb.sv` 单独展开一种深度，测试台应将参数传给 DUT 并在输出中打印其实值。用固定种子产生带唯一标识的输入词，在各实现上重放。一个能辨别非二次幂回绕错误的测试，应在临时副本取消显式回绕时报出首个失配的配置、周期及预期/实得数据。保存原始设计和对应的失败输入，按覆盖到的参数和协议条件报告结果。[Icarus 展开参数与顶层选择](https://steveicarus.github.io/iverilog/usage/command_line_flags.html#elaboration-flags)
