# 工程研究怎样写成博士论文

收到架构说明、项目验收书、一组小论文或工程实验结果时，先回答一个问题：读者掌握了本文哪一项新知识或工程方法，可以据此做出什么原先难以做出的判断？据此决定正文值得展开的内容。

## 先认清论文和成果的类型

- **学术博士做工程课题。** 从原型和实测中找能接受检验的学术问题，例如一种失效现象的成因、一项设计原则的适用边界，或一种测量方法能发现的既有盲点。系统在这里也可以是原创成果，需要说清它改变了什么既有认识或能力，以及证据如何支持差异。
- **中国工程类专业博士写学位论文。** 围绕实际难题、作者独立承担的工作、新方案及其实施效果组织。工程约束与使用证据应足以判断实践创新的意义。学位办〔2024〕18号的对象是八个工程类专业学位类别，具体要求需结合培养单位细则。若用户采用规定的实践成果申请路线，再按该路线核对可展示实体、总结报告和相应评价材料。[国内学位论文流程](dissertation-workflow.md) · [工程类专业博士试行要求](moe-professional-doctorate-2024.md)
- **境外项目与期刊稿。** 根据具体项目或稿约确定所交文本。英国 Warwick 的 EngD 作品集与该校普通 PhD 的学位论文要求各有适用对象。由博士论文压缩成期刊稿时，选一个读者最需要解决的问题，保留使该判断成立的全部关键证据。[Warwick 研究学位指南 §§1.3、1.7](https://warwick.ac.uk/services/dc/submission/gtehdr/)

## 从任务书中抽出研究问题

1. **重建故障或瓶颈。** 从需求、现场记录或预实验中取出一个有代表性的工况，交代谁使用系统、输入和约束是什么、既有做法在哪里失效、后果如何观测。用实测、规范要求、估算或使用方意见各自真实的身份来写。只有“企业需要提高效率”时，先回查等待发生在哪个环节以及如何计时。
2. **找出改变成败的设计决策。** 选择一个技术上可行的近邻方案，以同一输入走过原方法和本文方法。指出哪个模块在何时获得了不同信息、修改了哪一步状态、可能付出什么资源或时延代价。将实际比较过的方案与仅经过可行性分析的备选分开。约束改变会翻转选择时，把这个条件写入讨论。[NASA 系统工程手册 §6.8](https://www.nasa.gov/reference/6-0-crosscutting-technical-management/)
3. **界定个人增量。** 查对平台已有能力、团队共建的部分、个人负责的决策和可核查产物。例如，项目交付了一台整机，论文可以明确作者设计了哪一级控制器、完成了哪些试验，谁提供整机平台和部署条件。技术归属未知时保留待核项。成果清单和部署证明可指引核查，正文仍要解释作者做出的技术改变。
4. **将证据接回原问题。** 验收记录支持在指定条件下达标。要声称优于现有方案，需能辨别方法差异的对照；要归因于某个机制，还需解释同时变化的因素，用消融、追踪或独立观测排除与主张相竞争的解释。仿真、RTL、原型和现场各写明所测层次。声称现场效益时说明版本、工况、观察区间、分母与比较期，并查同期是否更换平台、负载或操作流程。[工程实验设计](experiment-design.md) · [Runeson 与 Höst，案例研究设计及效度](https://link.springer.com/article/10.1007/s10664-008-9102-8)

### 一段样稿怎样收窄到证据所及

原句示意：“本文结合进化搜索构建了高效的片上网络调度系统，显著提升网络性能。”其中“系统”是哪一层，“性能”是哪一个量，进化搜索是否比同预算的其他搜索更有效，现句均未说明。

已有材料是一个固定 XY 路由的 4×4 网格模型。改变的是源端待发包的注入次序，链路和路由保持相同。两种搜索各评价 24 组权重，使用同一组训练轨迹。固定权重后，每类负载的四个策略重放相同的 12 条留出轨迹。据此可以写成以下结果段。

> 在均匀与热点突发流量下，进化搜索选定的注入策略比 FIFO 分别少用 0.245 和 0.311 周期/包。同预算随机搜索选定的策略又分别比进化策略少用 0.077 和 0.004 周期/包。在这些轨迹上，改变源端注入顺序有平均时延收益；两次选参的对比尚未显示进化搜索带来的额外收益。

若“进化算子的作用”才是核心贡献，下一步应重复整个搜索过程，并在相同预算下比较算子替换后的策略。继续给这一个已选策略增加测试包，只能更细地描述该策略的表现。若要讨论硬件代价，还需相应实现和资源测量。此处的反例可以改变论文重心，也可以促成有针对性的补验；这组样本本身不能判定一项博士工作的充分性。

## 组织与修订长稿

先给每个工作章写一行：**本章解决的子问题、承接前文的已知条件、交给下一章的结果**。诊断章识别瓶颈，设计章解释如何利用它，评价章再检验瓶颈是否解除、代价是否移到别处。若几章是并行路线，用统一约束、共同评价或适用工况把它们在综合章接起来。后章并未使用前章产出时，勿造一条虚假的依赖。已发表的章节分别检查实验平台、版本和单位是否仍可横向比较。

| 原稿症状 | 修订动作 |
| --- | --- |
| 创新点逐条列出模块名，正文只有功能框图 | 取一个输入走完旧方案和新方案，在图或时序记录上标出首次发生差异的位置。保留支撑这一决策的模块，通用配置移到实现说明。 |
| 同一项目的多份材料各算一项创新 | 归并支持同一主张的专利、实现、测量和应用证明。在[贡献卡](../templates/contribution-card.md)中写清近邻、独立增量及证据落点。 |
| 模型推导、仿真曲线、现场结果各成一章却互不解释 | 核对模型中可观测的量和试验中的口径，挑出吻合处与偏差最大的工况。查清模型约化、测量条件或实现差异能否解释偏差。 |
| 修改意见只说“创新性不足” | 找到被质疑的具体句子，判断缺相近工作、机制差异、有效对照还是作者分工。能补材料就补到正文；条件缺失就调整摘要、章节小结、图题及结论中的同一主张。 |
| 工业合作数据受限 | 核对可披露范围。在授权范围内提供可审查的单位、归一化基准、代表工况或替代验证。分别说明替代材料能证明什么、现场数据还有哪些部分不能独立核查。 |

架构图可以定位作者改变了哪段路径，时序图或实测图解释改变何时生效，对照表呈现收益与代价。用[工程论文图表指南](engineering-figures-tables.md)选图、制图并核对最终版面。若已收到整章原稿或评阅意见，用[工程修稿指南](engineering-revision.md)把同一条件追到摘要、题注和结论。
