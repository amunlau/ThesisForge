# 专家意见回复、两稿对照与覆盖核查

在用户要求逐条答复专家/导师/审稿意见、生成学位论文修改说明、比较原稿与改稿、整理修改对照表或核查现有回复时加载。普通润色仍按原范围处理。格式制作见[文档工作流](document-workflows.md)，整稿返修及投稿材料见[修订与提交](revision-and-submission.md)。

## 先识别交付任务

| 委托 | 实际工作与边界 |
| --- | --- |
| 起草逐条回复 | 读取意见、当前稿及可用证据；有原稿就比较。“作者报告已完成”与“已经查到实际修改”分别记录；不因写回复自动改正文。 |
| 改论文并回复 | 在已有授权范围内修订、补分析或执行实验，核对实际结果，再将真实动作写入回复。已明确的处理方向不逐条重复请求批准。 |
| 只做两稿修改说明/对照表 | 比较实际两稿，说明增加、删除、改写、移动和未核区域；没有专家意见就不生成虚构意见、采纳率或专家覆盖率。 |
| 核查已有回复 | 对照原意见、两稿与回复，报告漏项、虚假/未核实完成声明、定位错误、状态冲突和改稿退步；没有改稿权限时不改正文。 |
| 只更新页码/行号/表号 | 保留评论原话、回复内容和其他格式，只更新要求的定位字段并核对其所指对象。原评论内的旧页行不是待全局替换的错误。 |

目标决定外观：期刊修回信、会议短 rebuttal、学位评阅修改说明、导师批注处理记录、学位论文抽检相关回复/整改说明可以共用证据过程，但不共用默认表头、审批、匿名、限字或提交要求。抽检任务先读实际通知、问题认定、学校提供的表格及签章/责任要求；没有材料时先完成事实对照和回复草稿，不声称符合某个统一教育部回复模板、不替学校或作者作通过/批准声明。

## 锁定原件、版本与阅读范围

原意见、原稿、最新修改稿、标记稿、清洁稿和已有回复分别登记身份、用途、轮次、文件指纹及实际已读范围。`round` 与审稿人编号分开；例如第二轮的 R1 不等于第一轮的第二位专家。文件名、修改时间、旧会话中的记忆和“最终版”后缀都不能单独确定正式基线。用户仍在编辑的未保存内容不能冒称已包含在磁盘快照里。

沿用[项目记录](evidence-ledger.md)的材料和问题 ID。[回复台账](../templates/reviewer-response-ledger.json)是这项任务的可检查视图，不与项目记录另建两份相互冲突的事实。采用现有表格也可以，先保存足够的身份、证据和覆盖信息，再根据需要导出回复、对照表及核查结果。

| 可得材料 | 可以确认什么 | 暂时不能确认什么 |
| --- | --- | --- |
| 意见及原稿、改稿 | 在已读取范围内核对应问题、两稿差异和完成声明 | 未读对象或仅靠文字无法判定的图、公式、版面 |
| 只有意见与改稿 | 当前稿是否包含相关内容，如何回应已有内容 | 相对未取得基线的新增/删除、是否“本轮补充” |
| 只有两稿 | 两稿差异与保真情况 | 是否覆盖未提供的专家意见，评审是否认可 |
| 只有意见或回复 | 拆问题、整理处置草案、检查回复内部一致性 | 独立证实正文已改、实验已做、页码正确 |

先完成不依赖缺件的工作。缺材料用“未提供/未核实”，不能换成“没有做/没有改”；确实检查两稿后发现声明不符，再记录明确矛盾。

## 建立意见全集与子问题清单

1. 保留原件，分别读取编辑通知、专家评阅书、正式评论、Word 批注、PDF 批注及随附清单。正式意见、导师建议、内部模拟评审与助手推测的读者需要标明来源类别。
2. Word 批注核批注正文及其锚点；PDF 批注核内容、高亮/圈注区域和页面。普通文字抽取可能漏批注、扫描页或附件；扫描/OCR 要回到原图核对数字、符号、否定和编号。抽取版本另存，保留原件 hash 及提取方法；自动去页眉、合行或去重不改写唯一原文。
3. 保留专家原编号与完整原意，再给稳定工作 ID。复合意见拆成可分别回应的子问题，每个子项指回原意见及准确短引；短引的字面匹配不能证明拆分已经穷尽。不要因为编号不连续、重复或跨页就丢掉意见。
4. 同一问题被不同专家提出时，各自保留条目。一处改动可关联多个子问题，但每个子问题仍需说明该改动如何回答它；同一原意见中的补实验、解释原因和修改表述也不能只答其中一项。
5. 清点实际源范围与提取范围。只有确认意见原件已完整读取、所有子问题均有对应处置，才能报告该范围内的覆盖情况；不能以“登记了多少就全部通过”代替原件完整性。

## 动作、执行事实与问题解决分开

先辨识问题根因：描述不清、两处不一致、证据不足、比较不公平、贡献范围、格式要求、或已被当前稿回答。评审提出某个实验并不自动证明它是唯一正确修法；保留有据分歧，也不为迎合意见删除有效定义或限制。

| 处理选择 | 回复必须说明 |
| --- | --- |
| 采纳并修改/补充 | 具体改了什么、所用依据、改后位置；新增实验只引用真实执行与结果。 |
| 部分采纳 | 已处理的子问题、未处理部分、依据及对结论的影响。不能用一个“已修改”覆盖整条。 |
| 澄清已有内容 | 原文已有的定义/数据/范围及位置；本轮没有改就不说本轮新增。若另改表述，再分别说明。 |
| 有据不采纳 | 回答实际关切，明确理由、现有证据和保留的限制；不假定作者已承认错误。 |
| 计划或未来工作 | 真实未完成状态。补写展望文字只证明改了文字，不证明已执行所建议的实验。助手的候选建议不自动成为作者承诺。 |
| 意见相互冲突 | 保留双方条目、指出冲突及有据取舍；需编辑或学校判断时说明待决事项，不虚构已获认可。 |

同时记录三层事实：**做了什么、有什么验证、关切是否得到回答**。作者称完成，记录为作者报告；文件变化被核到，记录实际比较位置；认为问题解决还须给依据和剩余限制。覆盖、采纳、完成、文件核对、科学问题解决不是一个比例，也不自动推出专家满意或通过。

## 实际比较原稿与修改稿

先比较稿件和数据，再看回复的说服性语言。按章节、自然段或具体对象匹配，既查删除也查新增。关键差异记录两稿位置、原片段、改后片段、关联意见及证据；移动内容核目标位置与原使用点，重复文本需结合上下文辨识。确认没有变化时允许如实写无变化，不为了显示工作量强行改稿。

原稿是基线，研究证据才决定正确性。分别判断：有益压缩、有据订正、合理迁移、信息有害丢失、无据新增和无法核对。核定义、比较对象、分母、条件、否定、量词、机制推理和结论强度；全部数字相同也可能改变科学含义。必要时继续用[保真检查](natural-writing-and-review.md)和真实数据复算。

可用跨平台只读助手建立提取快照和字面对照：

```text
python <技能目录>/scripts/compare_manuscripts.py snapshot reviews.docx --view final --output reviews-snapshot.json
python <技能目录>/scripts/compare_manuscripts.py compare original.docx revised.docx --before-view final --after-view final --output-dir comparison-01
```

输出目录必须新建；对照产出 `before.json`、`after.json`、`changes.json`、`changes.md`。文本/DOCX 使用标准库；PDF 需要实际可用的 PyMuPDF。默认严格 UTF-8，旧中文纯文本可显式 `--encoding gb18030`。这些产物提供来源身份、可读取单元、定位及有限差异，**不是语义解决证明**。读取每份产物的覆盖限制；图像、公式对象、格式、批注锚点及最终页行仍须对应工具和视觉检查。

DOCX 的 `final`/`original` 是对现有插入/删除标记的只读内容投影，不接受或拒绝原文件修订；`original` 不能恢复未被记录的历史改动。标记稿与清洁稿应比较相同的最终内容投影，再核对象与版面。真实 Track Changes、文字变色、底纹和差异重建是不同产物；不能将新生成的比较结果说成历史修改人及编辑过程。

TeX 对照只处理明确指定文件的字面内容，不展开整个多文件工程。先用[稿件审计](../scripts/audit_manuscript.py)确认读取范围，再逐一比较受影响源文件及图表/数据；源代码差异与最终 PDF 内容另核。Git 可以提供额外基线，未提交快照也可使用；同一文件有差异不代表这条意见所要求的内容已改。

## 页码、行号和编号的有效期

| 定位 | 含义与核法 |
| --- | --- |
| 原意见内的页/行/图号 | 属于专家看到的原稿；原话保持原样，必要时旁列原→新映射。 |
| PDF 页序 | 文件中的物理页面顺序，注明从 1 计数；不同于可能从罗马数字或其他数值开始的标签。 |
| PDF 页面标签 | 文件内的导航元数据；未必等于页面上实际印出的页码。 |
| 印刷页码/边栏行号 | 在实际提交文件中显示的页/行，按真实渲染核读；不能用 `.tex` 行号或 DOCX 段落序号替代。 |
| 节/段/标签/图表对象 | 相对稳定的辅助定位，仍需绑定本次版本；一个节名出现不能证明具体改动存在。 |

事先确定学校/刊物要定位清洁版、全部修订显示版还是其他视图。Word 显示删除内容、批注气泡或不同标记方式会改变分页；`final` 内容快照并不是 all-markup 页面。现有 [Word 导出](document-workflows.md)的默认导出不能自动证明特定修订显示视图正确。按要求用实际后端生成/查看该视图，记录文件 hash、渲染器、视图和检查日期；没有条件时给已核章节/对象，页行列待核。

改动、字体/模板变化或重排后，旧定位与验收可能失效；检查受影响范围，不能用旧 aux 时间、固定页码偏移或上次截图补齐本次页行。正式回复中的改后摘录、图表号、数值必须在所声明版本找到并符合其上下文。

## 生成回复、修改说明与对照表

采用[逐条回复模板](../templates/reviewer-response.md)或[修改对照模板](../templates/revision-comparison.md)，字段按真实目标裁剪。先直接回答关切，再解释证据、实际动作和位置；短致谢即可。回复可以说明修改经过，论文正文应直接解释技术内容，不插入面向审稿人的辩护话语。

自写答复和修改说明同样按[篇章衔接判据](natural-writing-and-review.md#突兀与篇章衔接检查)核对象、执行主体、段落任务与句间关系。专家原话和逐字摘录保持原样；说明与引语分清。衔接优化不能把计划写成完成、文字调整写成新增实验，或给尚未证实的关系补原因。

说明既支持已修改也支持有据维持。不要把改善措辞写成做了实验，把作者自报写成独立核实，把没有提供旧稿写成查明未改，也不把学校签字、共同作者同意或专家认可填成模板默认事实。多轮回复中“已于某版本修复”需要那一历史版本的证据；只有当前稿不能证明具体修复日期和轮次。

中英双文件或正文/表格两种输出由同一台账形成，逐项同步意见 ID、动作、状态、数值、限制和位置。工作稿可有明确待核项；对外稿清除内部提示时仍保留影响判断的事实缺口。若目标要求全部完成而仍有关键缺口，交草稿和清晰缺口表，不将其包装成可正式提交版本。

## 覆盖与终检

从台账生成检查结果：

```text
python <技能目录>/scripts/audit_reviewer_response.py case.json --root . --output response-audit.json --markdown response-audit.md
```

按[台账字段与工具边界](reviewer-response-schema.md)及[空台账](../templates/reviewer-response-ledger.json)填写实际来源和条目，输出必须是新文件。静态助手检查其支持范围内的身份、关系、摘录、状态和覆盖；查看 `--help` 及检查输出的限制。`--strict` 是显式选择的结构/一致性门槛，不能将其通过称为论文、回复语义或学校审查已通过。

交付前分开回答：

1. **原件范围**：哪些意见、附件、批注和扫描页读过，哪些未读取/未能提取；总体是否已确认完整。
2. **条目覆盖**：已确认原意见及子问题数量、已有回应、明确待办和漏项，重复/共享项如何计数。
3. **声明核对**：回复中每个完成声明、摘录、数字、证据和位置是否与具体稿件一致；是否存在只有作者报告的部分。
4. **解决与保真**：每项回应是否回答了实际关切，改稿是否引入新的丢失或无据主张；移位后指代、条件和引文支持范围是否保持；语义复核的实际范围。
5. **成品定位**：clean/marked/回复/对照表是否同版，页行是否来自指定视图的当前成品，学校/刊物要求的材料是否齐备。

上游意见改变、稿件/数据更新或人工改动回复后，按影响重新核查。审计成功不代表已提交、专家已认可或无需作者核实事实。达到本次委托范围且处置真实可追溯即可交付；不因为模板栏目多就扩大到整稿改写，也不以固定循环次数遗留仍可修的错误。
