# 接入与模式

在检索文献、改格式或开写正文之前，先确认当前任务有足够输入。缺的是关键约束就一次问清；缺的是可后续补的细节则先推进内容与逻辑。

## 先识别三类输入

- **题目主导。** 先确定研究对象和可用证据。若要求自行实验并成文，由执行者完成文献比较、可行性检查、实验、分析及初稿。若只要求选题或方案，以相应成果结束。
- **材料主导：** 用户已有开题报告、章节、数据、代码或审稿意见。以这些为事实来源，草稿中的推测要核对。
- **混合：** 已有部分稿和数据，同时需要补文献或补实验。分别标记“已有证据 / 待补实验 / 本次推导”。

## 核心字段

下列字段用于识别任务。主题和预期成果足以启动自主计算实验。按某校或某刊定稿时再核对相应模板和稿约，目录未知时先完成研究与通用稿件。

1. 产品类型：学术/专业，硕士/博士，或期刊/会议（含目标刊物名，若已有）
2. 研究主题或核心问题
3. 任务模式：`topic` / `design` / `execute` / `analyze` / `write` / `review` / `polish` / `rebuttal` / `revision-diff` / `response-audit`
4. 约束材料：学校模板、刊物作者指南、已有稿件或数据

以下信息可由委托、已有材料或合理默认值确定。只补问会实质改变本次交付且无法推断的事项。

- 原文/目标语言、地区与著录体例分别识别；新写默认中文，未要求翻译的编辑保留原文语言，学位论文双语摘要按学校模板确定
- 深度：`quick` / `standard` / `deep`（默认 standard）
- 子领域：系统与应用、机器学习、通信、半导体/电子，或交叉
- 已有发表、前序会议版、合作者分工
- 时间预算和本轮只要哪一章/哪一项

不要默认替用户发明学校名称、摘要字数、页边距或盲审分数权重。

专家意见任务先盘点真实存在的原始意见、原稿、修改稿、标记稿/清洁稿、回复草稿、最终 PDF 与学校/刊物表格，按角色及版本命名。先利用可读材料，不把整套材料到齐当作整理意见的门槛。只有修改稿可检查当前内容，却不能独立确认本轮新增；没有修改稿仍可准备回应结构，不能声称已经完成并核过修改。只要求双稿说明时不额外虚构审稿意见；只要求回复核查时不擅自改正文。具体见[逐条回复与对照](reviewer-response-workflow.md)。

## 深度

| 深度 | 典型用途 | 文献与检查力度 |
| --- | --- | --- |
| `quick` | 看摘要、改标题、单章局部润色 | 只核对眼前主张与已给材料；不做系统检索 |
| `standard` | 常规撰写、通章审查、实验方案、按刊初稿 | 按委托核对相关材料和检查项，研究与选题任务再核对照文献 |
| `deep` | 开题级选题、预答辩/盲审级通审、系统调研 | 在指定范围内深查关键主张及原始依据。系统调研可作路线比较和反证检索，通审再做全文一致性核对 |

深度与篇幅分开选择。单段也可以深查，局部润色不因选 `deep` 而扩成全稿审查。涉及文献工作时看质量：被保留为对照或背景的条目要真正读到能支持判断的部分。只堆题目和摘要不算完成。

编辑目标（语法、清晰度、简洁、篇章组织）与允许变化（局部文字、结构、已授权事实订正）独立确定。用户已说清的范围直接沿用，不为了填表反复询问。`deep` 可按核心贡献的风险选择方法、证据/引用、工程实现或读者逻辑等独立复核视角；普通局部任务使用一个执行者即可。成本和可用能力不足时合并角色，说明实际覆盖，不假称已由多位领域专家审阅。

用户明确要辅导或讨论时，可采用逐章问题引导，让作者解释问题、材料、机制和关键证据；用户要求自主研究与完整交付时，先提出合理候选并按既有授权推进，不能把导师式提问变成每阶段确认门槛。选题诊断给“可进入小规模验证/需缩小范围/缺关键条件”及决定性依据，不以数值分数背书创新性或录用概率。

## 编辑范围

普通润色默认允许指定范围内的句内及相邻句拆合、必要的段内调序，保留独立信息和技术含义。识别出跨段/跨小节的结构问题仍要报告，但未获相应授权时给出具体拆合点或移位建议，不直接改动段落边界或范围外正文。可读邻近上下文厘清指代，不能据此扩大改稿范围。

用户明确要求“整理段落、调整层次、结构重写”等，即可在指定范围内拆段、合段和移句；无需再要求固定模式词或逐项确认。仅审阅时保留原文和边界。深入检查或 `deep` 只改变核查力度，不自动授权结构重组或事实订正。

已有标题默认保留，改题另提建议；用户已授权改题或章节重组时按范围执行，并核对受影响的目录、书签、页眉和交叉引用。结构调整不授权新增机制、改变证据归属或科研结论；证据不足时列待核，不用过渡句掩盖。判据与终检见[自然写作](natural-writing-and-review.md#突兀与篇章衔接检查)。

## 题目锁定

新题目或用户已有明确边界时，用简短锁定（可写在工作笔记或报告开头，不必单独建很多文件）：

- 要回答的问题 / 非问题
- 贡献类型（理论、方法、系统、测量、应用或工程方案）
- 评价方式（测量、仿真、实现、证明）及不可用的捷径
- 目标读者：答辩委员会或某类刊物

后续检索或设计明显偏离锁定时，先说明偏离和选项（收回检索，或改锁定），不要悄悄把题目改成更好写的方向。

## 输出约定

- 写作和润色优先给用户所需正文，再列重要修改或未解事项；选题、审阅和状态任务先给判断及可执行动作。用户明确指定的输出顺序优先。
- 仅审阅时保留正文，交有定位的意见。仅润色时改指定范围的表达，技术冲突另列。用户明确要求直接纠错或实质修订时，据证改正指定范围内的问题，并复查关联位置。兼要审阅件与润色件时从同一原稿起步，逐条注明修改或待核状态。交付格式按用户要求。
- 文字意见定位到原句，图表意见定位到具体图元、面板或行列，缺失项注明应出现的位置。按[自然写作与文稿终检](natural-writing-and-review.md)标问题类别与影响程度。确无实质问题时交代核过的范围。
- 所有模式的最终文字输出都做自然表达、衔接、错误和保真检查；深度不改变证据边界。最终版本回读后再交付；读取或版面检查受限时说明位置及受影响判断。
- 工作笔记里可以用内部标签（supported / qualified 等）；论文正文用自然的条件与归属来写，不把标签印进去。
- 学校或期刊模板一旦提供，立即覆盖本技能的默认结构中对应格式项。

长稿恢复沿用[项目记录](evidence-ledger.md)中的实际材料、决定和检查状态。Word/LaTeX 构建、匿名稿、投稿包、系统综述、benchmark 等按本次任务加载对应参考；仅因提到论文或期刊，不启动所有扩展流程。未知的学校、刊物或工具并不阻止可独立完成的内容工作。
