# 接入与模式

在检索文献、改格式或开写正文之前，先确认当前任务有足够输入。缺的是关键约束就一次问清；缺的是可后续补的细节则先推进内容与逻辑。

## 先识别三类输入

- **题目主导。** 先确定研究对象和可用证据。若要求自行实验并成文，由执行者完成文献比较、可行性检查、实验、分析及初稿。若只要求选题或方案，以相应成果结束。
- **材料主导：** 用户已有开题报告、章节、数据、代码或审稿意见。以这些为事实来源，草稿中的推测要核对。
- **混合：** 已有部分稿和数据，同时需要补文献或补实验。分别标记“已有证据 / 待补实验 / 本次推导”。

## 核心字段

下列字段用于识别任务。主题和预期成果足以启动自主计算实验。按某校或某刊定稿时再核对相应模板和稿约，目录未知时先完成研究与通用稿件。

1. 产品类型：学术/专业，硕士/博士，或期刊/会议（含目标刊物名，若已有）
2. 研究主题或核心问题
3. 任务模式：`topic` / `design` / `execute` / `analyze` / `write` / `review` / `polish` / `rebuttal`
4. 约束材料：学校模板、刊物作者指南、已有稿件或数据

以下信息可由委托、已有材料或合理默认值确定。只补问会实质改变本次交付且无法推断的事项。

- 中文或英文（默认中文；学位论文摘要通常中英都要）
- 深度：`quick` / `standard` / `deep`（默认 standard）
- 子领域：系统与应用、机器学习、通信、半导体/电子，或交叉
- 已有发表、前序会议版、合作者分工
- 时间预算和本轮只要哪一章/哪一项

不要默认替用户发明学校名称、摘要字数、页边距或盲审分数权重。

## 深度

| 深度 | 典型用途 | 文献与检查力度 |
| --- | --- | --- |
| `quick` | 看摘要、改标题、单章局部润色 | 只核对眼前主张与已给材料；不做系统检索 |
| `standard` | 常规撰写、通章审查、实验方案、按刊初稿 | 按委托核对相关材料和检查项，研究与选题任务再核对照文献 |
| `deep` | 开题级选题、预答辩/盲审级通审、系统调研 | 在指定范围内深查关键主张及原始依据。系统调研可作路线比较和反证检索，通审再做全文一致性核对 |

深度与篇幅分开选择。单段也可以深查，局部润色不因选 `deep` 而扩成全稿审查。涉及文献工作时看质量：被保留为对照或背景的条目要真正读到能支持判断的部分。只堆题目和摘要不算完成。

## 题目锁定

新题目或用户已有明确边界时，用简短锁定（可写在工作笔记或报告开头，不必单独建很多文件）：

- 要回答的问题 / 非问题
- 贡献类型（理论、方法、系统、测量、应用或工程方案）
- 评价方式（测量、仿真、实现、证明）及不可用的捷径
- 目标读者：答辩委员会或某类刊物

后续检索或设计明显偏离锁定时，先说明偏离和选项（收回检索，或改锁定），不要悄悄把题目改成更好写的方向。

## 输出约定

- 对用户先给判断或可执行的下一步，再给稿件或审查意见。
- 仅审阅时保留正文，交有定位的意见。仅润色时改指定范围的表达，技术冲突另列。用户明确要求直接纠错或实质修订时，据证改正指定范围内的问题，并复查关联位置。兼要审阅件与润色件时从同一原稿起步，逐条注明修改或待核状态。交付格式按用户要求。
- 文字意见定位到原句，图表意见定位到具体图元、面板或行列，缺失项注明应出现的位置。按[自然写作与文稿终检](natural-writing-and-review.md)标问题类别与影响程度。确无实质问题时交代核过的范围。
- 所有模式的最终文字输出都做自然表达、衔接、错误和保真检查；深度不改变证据边界。最终版本回读后再交付；读取或版面检查受限时说明位置及受影响判断。
- 工作笔记里可以用内部标签（supported / qualified 等）；论文正文用自然的条件与归属来写，不把标签印进去。
- 学校或期刊模板一旦提供，立即覆盖本技能的默认结构中对应格式项。
