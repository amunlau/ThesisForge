# 论证与逻辑

专家级审稿看论证是否闭合，不看套话是否齐全。本节约束全文逻辑和主张强度。中英文措辞分档、摘要人称冲突的细则见 [写作与润色](writing-and-polish.md)。

## 主张—证据—warrant—范围—局限

下列五段是对 Toulmin 模型（claim / grounds / warrant / qualifier / rebuttal，另有 backing）的教学转写，用于工作检查，不是原书六件的逐项等同，也不作为正文必须出现的小标题。Toulmin 原书 *The Uses of Argument* 本轮未打开，不编页码。「证据」对应 grounds，不是 warrant；「范围」接近 qualifier，写的是主张在何种条件下成立，不要反过来鼓励堆情态动词；「局限」接近 rebuttal / limitations，不完全等于原书的 rebuttal；本转写未纳入 backing。

每一条重要判断在工作检查中应对得上：

- **主张：** 究竟断言了什么（贡献、结果或限制）
- **证据：** 文中真实存在的定理、测量、消融、比较或引文
- **warrant：** 为什么这份证据够支撑这个主张（指标是否测的就是这件事、基线是否对、假设是否成立、样本是否够）
- **范围：** 主张打算在什么条件下成立
- **局限：** 真正可能使它失败的条件，而不是仪式性的“效度威胁”段

专家审稿的四个问题（Sewell）：动机是否真实？主张若成立是否构成实质进展？证据是否撑住主张？对具备背景的读者是否写清楚？其中任一项明确为否，在严肃刊物上就足以构成拒稿理由。相反，下列不是合格审查意见：只是想看另一篇不同类型的论文；在主张已被合理支撑时仍强求更多实验；因为想法“太简单”或属于诚实的增量改进就否定；把漏引审稿人自己的文章当成致命伤。四问及坏理由出处为 CACM / *Plan Perspectives* 评审随笔（现场本轮 HTTP 403，已用 Internet Archive 存档核对）及作者 GitHub 维护稿。

学位论文同样用这四问做通篇逻辑检查，再补一条：各章是否服务于同一个学术思想。

## 主张三档（写和改时强制使用）

1. **直书。** warrant 强：在点名且公平配置的基线上，有重复和变异性报告的 12% 降低，就写成 12% 降低，不要改成“可能在一定程度上倾向于有所降低”。
2. **限定范围，不起雾。** warrant 只覆盖部分条件：写“在数据集 D 与模型 M 上……；是否推广到……尚未验证”。用条件状语，不用一串情态动词。使结果成立的条件紧跟该结果，影响迁移的共同局限可集中在讨论中。
3. **不主张。** 证据缺失时，不要用“据信、不难看出、理论上应该、实验将表明”把空缺写过去，也不要编造实验。

同时避免：

- **过虚：** 首次、填补空白、国际领先、通用、最优、新范式、把仿真写成真实硬件已验证。没有检索边界和对照，就不要写这些词。计算机学报等要求摘要「体现创新」，并不等于授权使用宣传形容词。
- **过防：** “据我们有限的所知或许可以谨慎地建议……”；罗列琐碎风险却把真正局限藏起来

局限集中写在讨论、结论或方法适用范围里，写对判断有影响的那些。不要给每个句子加防御前缀。清华 2025-03 指南要求在结论中阐述创造性工作，并实事求是，除非有足够证据，应避免「首次」「领先」「填补空白」等用语。这是把主张写紧，不是许可形容词竞赛，也不是要求把每句都写成保险条款。

评阅人问的是主张是否清楚、紧凑，不是句子是否足够对冲。第 2 轮曾见西电评阅书「创新点是否明确、凝练」的是否栏，本轮未能重核（原页 13806 HTTP 404、无存档），不得再当作已重核依据。见 [审查量表](review-rubric.md)。

## 段落与章节逻辑

- 一段一个主要关系。先给判断（主题句），再给证据和必要限定。这是推荐写法，与武大计算机学院写作规范、Nature Education Scitable “Scientific Papers” 的建议一致，不是把无主题句段落自动升为主要项的审查硬规则。
- 有因果才用“因此”，有真正转折才用“然而”；两件事实只是并列时，不要强加对比。
- 相邻段落要接得上：上一段得到什么，下一段解决哪个还没解释的问题。
- 引言可用「情境—需求—本文任务—文档对象」迅速进入贡献，不要把引言写成作者经历回顾。英文稿把贡献前置、写具体。
- 结论解释结果的意义并回到开头的问题，不要只重复摘要，也不要引入新证据。学位论文结论按 GB/T 7713.1—2025 5.3.7：核心观点、局限、后续工作，不是各章小结的复述。
- 相关工作对比要准确、克制；被你一笔抹杀的作者可能正是审稿人。

## 全文一致性

对“读起来突兀”的位置，用 [突兀与篇章衔接检查](natural-writing-and-review.md#突兀与篇章衔接检查)：先辨认本段任务，再查前提在首次需要时是否可获得、指代是否明确、连接词所连关系是否成立。只在读者无法合理补链或补错会改变论断时列意见，在首次影响理解处给最小修法；上下文已说明的对象不重复报错，也不逐句强加过渡词。

检查这些位置是否在讲同一个故事、同一组条件、同一组贡献：

- 题名是否覆盖真实工作范围，有没有开空头支票
- 摘要、绪论/引言贡献、各章开头、结论创新点（创新点写在第1章还是结论，以学校为准；已打开的北大 2018/2019 写作指南、2007 年《基本要求与书写格式》，以及清华 2025-03、东南、西工大、华科、南大 2007 试行规定，均未把创新点定为第 1 章必备标题，创造性工作主要在结论阐述，不得恢复「北大必须第 1 章」，见 [学校叠加层](school-overlays.md)）
- 方法是否真的在回答所提问题
- 实验指标是否对应主张，而不是对应另一个更好看的数字
- 图表、符号、术语是否一处一种含义
- 各章是否服务于同一条学术思想，而不是把无有机联系的已发表小论文简单装订。这是默认质量立场（北大 2018/2019 写作指南第 2 章「通常学位论文只能有一个主题（不能是几块工作拼凑在一起）」、清华 2025-03「通常只能有一个主题」、中科大 2026-10-29 模板「通常学位论文只能有一个主题」、国科大 40 号「必须是一篇系统的、完整的学术论文」、上交 2025-11「基于……系列成果撰写的系统的、完整的学术论文」、武大计算机学院 2023-09、华东师大学术型《基本要求》第七条），不是《学位法》条文。同份北大指南第 1 章仍允许「一篇（或一组相关论文组成的一篇）系统完整的、有创造性的学术论文」（2007 年 6 月《基本要求与书写格式》已有同一句，为更早出处）——第 1 章与第 2 章两句同文件并存，须同时披露，不代选；与清华 / 中科大同向的是第 2 章写法，并不取消「一组相关论文」许可。不是用清华来覆盖北大，也不是北大只有后一句。各章仍须有机联系；不要把「一组相关论文」写成可以没有共同主题。不要把「一个主题」升为学位法，也不要退回百分之三十

发现不一致时，先查各处是否用了相同指标、对照与工况，再按与这项主张直接相关的可靠证据统一措辞。某个工况的收益可以直书，整个范围内的普遍收益需要每个所称条件都成立。会议扩展期刊仍以出版方现行规则为准，不要退回「百分之三十」口诀，也不要发明新百分比。IEEE PSPB Operations Manual（Amended 25 June 2026）8.1.7.F 要求「contain substantial additional technical material」，定量门槛只有该刊作者须知写明才存在；8.1.7.E 是基于学位论文的期刊文，须充分引用该学位论文，不要与 8.1.7.F 混成一条。TCOM / ComSoc 没有定量门槛，并否定「30% difference」为现行 IEEE 或 ComSoc 政策；8 页以上差异说明、75–200 词摘要及「可以原样复制文字图表」只作为 TCOM 专卡，不要套到全部 IEEE 或非 IEEE。TCOM 页引用的是「8.1.7.E」，现行手册把会议扩展写在 8.1.7.F：须披露这一字母可能不一致。ACM《Prior Publication and Simultaneous Submissions》（Reviewed April 2018）写 substantially revised「generally means that at least 25% … however, this is a somewhat subjective requirement that is left up to each publication to interpret」；具体比例以该刊现行规定为准，不要把总政策或 ACM TOCS 专卡套到所有 ACM 刊物，更不要套到 IEEE 或其他出版方，也不要与 IEEE / TCOM 混成一个百分比。见 [venues-acm-elsevier.md](venues-acm-elsevier.md) 与 [期刊论文流程](journal-workflow.md)。

**全文自洽六步检查**（可执行步骤；审查时按学校或刊物叠加，不要全国同一位置。出处：中科大 2026-10-29 模板、哈工大 2025-03 理工指南、国科大 40 号、上交 2025-11、华科校研〔2009〕39 号、南大 2007 试行规定、西工大 2025、通信学报稿件格式要求，以及既有 7713.1 / 清华 / 北大 / Sewell）：

1. 题名、摘要、第 1 章或引言贡献句、各章主张、实验/证明/仿真条件、结论或创新点卡片，是否在讲同一组对象、范围和条件；不一致时追回该项主张的原始证据，分清适用范围和反例。审查西工大 / 华科 / 北航稿时，对读摘要是否突出创造性成果或新见解（只作该校摘要职责，不必另造全国摘要词表）。华科各章「内容之间有严密的逻辑论证关系」、结论「归纳出若干有机联系的论点」，可并入该校叠加，不是新的全国主线法律依据。
2. 摘要是否整段复制结论或引言；结论是否只是各章小结的拼接（中科大、哈工大、国科大、上交、南大 2007 试行规定、浙大、7713.1）。南大（标明 2007 年文本及文学院「仅供参考」）：除绪论外各章小结须阐明本章所做工作、特别是创新性成果；结论不是各段小结的简单重复，并须写清自己完成的成果、特别是创新性成果。西工大 / 华科结论应阐述创造性工作及其意义，或归纳有机联系的论点；华科还允许「如果不可能导出应有的结论，也可以没有结论而进行必要的讨论」。北大 2014 年 4 月《研究生论文答辩和学位申请指南》形式审查提示「摘要不是引言的翻版」若使用，须标文件名，且只约束该校流程，不要算进 2007 年《基本要求与书写格式》本文，也不要做成全国禁令。
3. 方法中出现的设定、数据集、工艺或信道，是否在结果中出现；结果中出现的指标，是否在方法中交代（中科大）。
4. 图表、符号、假设是否被主张收窄或夸大；「首次 / 优于 / 显著 / 极大地改进」是否与证据同域。通信学报英文文摘对「极大地改进」「本工作首次实现了……」「经检索尚未发现与本文类似的工作」的禁例，只作为该刊英文文摘的可执行禁例，不要做成所有中文刊或学位论文的法定词表；学位论文侧仍用既有清华/北大「避免无证据的首次、领先、填补空白」与 Sewell 主张须被支撑。
5. 实验或仿真是否只给曲线和结论、不叙述条件与过程（哈工大理工指南）。通信稳态随机性能估计沿用 Pawlikowski 规程，有限批次核对初始化与终止事件，不写 BER 事件数。
6. 作者本人工作与他人工作是否分开（国科大结论「严格区分本人研究成果与他人科研成果的界限」、北大 2007 年《基本要求与书写格式》结论同样要求「应严格区分本人研究成果与他人科研成果的界限」、哈工大主体、软件学报「明确标引」）。0835 软件工程 2013/2014 年基本要求对他人论文、代码、文档、数据和工具「加以明确和规范的标示」，可作软件方向对步骤 6 的学科参考，不是全国新禁词。

不要把哈工大结论「避免使用『大概』『或许』『可能是』」或「结论一般 2000 字以内」、南大绪论字数、华科文献篇数、西工大第三人称摘要或通信学报英文文摘禁例做成全国默认；范围仍用条件状语写在适用处。不要把主题句先行升为审查硬规则。不要把 TCOM 的前作披露时限抄成学位论文规则。

## 不要当成硬规则的东西

- 创新必须是范式转移
- 凡仿真而无实测一律不合格（对许多通信与理论工作并不成立；器件/电路刊物则另有叠加规则）
- 相关工作必须第2章，或必须放最后
- 必须或不得使用第一人称（按语言和学校/刊物切换：GB/T 6447—2025 允许作者自撰摘要用「本文/我们」；已打开的北京大学 2018/2019 写作指南全文无此项禁令，不得把「摘要不用第一人称」写在该指南名下，也不得用它收窄 6447；该校 2014 年 4 月答辩指南印刷页 38 限制「我们」等群体性称谓、一般用「本文」，只约束该校流程，不能改写成全面禁止第一人称；通信学报摘要避免「本文」「作者」；清华 2025-03 指南未见第一人称禁令，不得用来收窄 6447）
- 必须有一个名为“效度威胁”的小节，且有了它就等于诚实
- 学位论文必须提交 artifact badge
- 每篇学术型博士都必须列出「至少三项」创新点，或评阅人必须列出三项、否则填「无」（复旦 2025 自然科学学术博士评阅书是申请人在三个编号栏「仅罗列要点」，不够填写可另附页；这是该校该表栏目，不是强制至少三项，也不是国家法律）
- 主题句先行、或正文必须按「先判断再证据」组织每一段（这是武大计算机学院与 Nature Scitable 的写作建议；若某段按时间或方法展开但仍能让有背景的读者看懂，不应仅因没有主题句就标为主要项）
- 把「承继—突破—价值」或「三条创新点」当成法定结构或审查硬规则
- 必须把学位办〔2024〕18号的专业学位大纲套到学术型计算机博士论文
