# 自然学术写作与文稿终检

本模块把 Unbot 的自然书面语、分类审阅、篇章衔接和保真终检方法内置到 ThesisForge，独立运行，不要求安装 Unbot。凡生成或检查论文相关文字均适用，包括选题说明、研究方案、结果分析、大纲中的实质陈述、正文、摘要、图表说明和审稿回复。局部任务只覆盖指定范围及理解所需上下文，不扩成整稿改写。

“AI 味检查”是对具体表达与论证缺陷的编辑审阅，不能据此判断作者身份、生成来源或给出 AI 生成概率；也不承诺第三方检测器通过率。目标是让本领域读者读到准确、自然、有依据的学术表达。外部检测报告只能提供待回读线索；未要求时不调用检测服务，不上传未发表稿件。AI 辅助使用及披露仍按学校或刊物规则处理。

## 按任务执行

遇到工程长稿中的章节跳跃、图文推理断裂或技术归属冲突，按委托范围回查实现记录与实验记录，给出能替换的段落或有定位的意见。数值全部吻合但事件成因写错的实例见[工程论文修订](engineering-revision.md)。

- `topic` / `design`：区分文献已有结果、作者设想与计划验证；不把预期收益写成已发生的改进。题目、研究问题与贡献说明同样检查空话和术语包装。
- `analyze`：先固定变量、样本、分母、比较基准和计算口径，再组织解释；观察、推导和机制推测分开。不能用流畅叙述补上尚未验证的因果。
- `execute` 的运行说明和实验日志使用实际命令、状态和产物位置。方法段区分设计时的预期、真实运行的配置和失败后采取的改动。
- `write`：先辨认材料支持的任务、方法与结果，再按“主题｜功能”组织长稿。正文用自然书面语；缺失依据列在作者待办中，不编入成稿。
- `review`：只审阅时保留正文，输出有定位的意见；用户要求直接修改时再改。未明确要求文件原生批注时，位置清楚的意见单即可，不擅自改变交付格式。
- `polish`：沿用原文语言、体裁、作者人称和已定义术语；准确得体的句段保留。仅改指定范围；可以读上下文以解歧，不顺带重写邻段。
- `rebuttal`：每项回复对应真实修改、现有证据或明确待办，复核回复与稿件版本、页码和实际改动一致；不把拟开展实验写成已补实验。

各深度均读完指定片段及必要上下文，并回读最终版本。`deep` 可深入追溯片段内主张的依据，修改范围仍按原委托。

## 先固定不能随润色改变的含义

修改前从材料中辨认并保留以下约束；长稿在工作记录中留下关键项，短文直接对照即可，不强制另建表格：

- 对象、样本与分母、对照组、时间窗、负载、信道或工况，以及仿真、测量、推导的证据类型。
- 数字及其变量归属、正负号、上下界、不等号、百分数与百分点、单位和幂次、统计量与展示精度。
- 条件、例外、否定范围、因果方向和不确定性；“仅、至少、尚未、可能、必须、建议”等分别限定什么。
- 术语、缩写、符号、公式、引文归属、图表和章节指向；代码、命令、标识符、链接目标及格式标记。

数字不变也可能改变含义：把两组数值互换、把“减少到”改为“减少了”、把“未发现差异”改为“没有差异”都须拦住。发现材料冲突时回查原始记录或作者指定权威版；无法裁定就并列具体出处，标“待作者核实”，不以更顺口的一版为真。语言润色不得暗中重算或更换争议数字。

## 起草与改写的编辑判断

先修事实和论证，再调篇章，最后改句。沿用 [写作与润色](writing-and-polish.md) 的中英文、人称和摘要规则及 [论证与逻辑](argument-and-logic.md) 的主张三档。

- **按段落的任务写。** 界定问题、比较路线、交代操作、报告结果或解释限制，各有信息职责。删除没有定位作用的预告和结尾重复评价；保留真正帮助读者寻找前提、区分条件的定义与提示。不强制每段“总述—三点—总结”。
- **用信息增量判断空话。** 试读删句后的段落：若对象、条件、比较基准、结果和判断强度均未损失，才考虑删去重复评价；若句子承担事实或机制主张，先核其依据。长稿定稿时再连读“主题｜功能”提纲，查孤段、题文不符和承诺未兑现。
- **让动作和对象明确。** “开展了系统性的误差分析工作”可简为“分析了误差”；操作已清楚时不必补虚构执行人。保留有作用的被动式，尤其英文方法段；不以主动语态比例评判自然程度。
- **用准确术语，不用同义词轮换。** “吞吐量”和“带宽”不能为避免重复互换；已定义的“鲁棒性”可以保留。抽象概念有定义、量化方式或推导作用时无需强行改成日常词。
- **把评价落到依据。** “显著提升系统效能”须核对应指标、基线和“显著”的含义。只有语言空泛才归文风；承担结论却找不到记录时归“依据待核”；已与表中数值冲突时归“事实与技术”。缺少数值时删去无依据评价或列待办，不为了具体而补造数据。
- **句法服从关系。** 条件归属不明、主语漂移或多项判断相互遮蔽时拆句；同一比较被切碎时可合并。不按词频、句长、连接词配额、随机标点造变化，不用闲谈、俚语、反问、比喻、编造经历或故意错字制造“人味”。
- **两种语言分别成文。** 中文核主语承接、动宾搭配和限定词位置；英文核主语、时态、单复数、冠词、指代及论断强度。中英摘要逐项对读对象、条件、指标、方向与结果，不只做逐词翻译。人称与语态按目标体裁和稿约切换。

## 突兀与篇章衔接检查

按读者实际阅读顺序连读，不只逐句扫描。对疑点先辨认当前段落回答的问题，再查前提是否已在前文、图例或术语表中提供，且在当前位置可找到。

1. **对象或层级突然切换：** 从系统吞吐跳到器件能耗、从总体结果跳到某子群时，检查研究关系、过渡问题和比较范围是否交代。首次引入时补材料已有的对象或调序，不靠添加“此外、值得注意”掩盖跳转。
2. **概念、基准或结果先于定义：** 首次说“降低 20%”却到后文才给基线，或“上述方法”无明确先行项，在首次影响理解处指出缺口；优先移动已有定义或点名比较对象。
3. **连接关系不成立：** 核“因此”的推导依据、“然而/相反”的真实对立、“这说明”的结论范围；相关性、结果先后或单一消融不能自行变成因果证明。若只是并列，去掉误导连接即可。
4. **跨章、图文或版本断链：** 移句后条件不再贴近结论、图题声称解释机制但图中只有性能曲线、回复中声称完成而正文没有对应修改，回查具体落点。

图表先独立读轴、单位、图例、样本与条件，再对照题注、正文引用句和章节标题；目测曲线不当精确读数。表中数字未在正文逐一重述，或摘要报告了正文图表中已有的结果，本身不算缺失信息。

只有读者无法合理补链，或补错会改变论断时才列意见。已由上下文消解的候选撤掉；不要求逐句复述主语、每段增加连接词，也不把没有主题句本身判为错误。大范围重排前保留原稿，优先提出最小可用修法。

## 六类问题与三级严重度

每条意见以 **【大类｜具体问题】** 开头，给出稳定位置、判断依据或对读者的影响，以及最小修法。文字问题附原文短引。图表缺标签、线形难以分辨或某材料缺失时，标出具体面板、曲线、单元格或预期位置。六类说明问题性质，影响程度沿用[审查量表](review-rubric.md)。

- **AI味与文风**：空泛评价、无信息的结构预告、机械复述、术语包装、装饰性限定。说明哪里没有信息增量，不只写“像 AI”；常规学术用语、自然重复和真实枚举不单独构成问题。
- **篇章与逻辑**：指代不明、比较对象迟到、概念跳转、因果缺环、章间断链。给出缺失前提及出现位置，不用泛泛的“加强衔接”代替诊断。
- **格式与排版**：编号、交叉引用、题注、字体样式或版面与适用模板冲突。区分提取文本异常与实际文件错误；不能凭文本抽取推断遮挡或溢出。
- **文字与语法**：错别字、漏字、搭配、歧义、英文语法和标点。只在改变理解或明确错误时标注，不把个人偏好写成语法错误。
- **事实与技术**：已有资料可证明的数值、单位、公式、指标、定义或技术关系错误。引用具体资料位置；修改后复查同一事实的所有出现处。
- **依据待核**：主张重要但在本次材料内找不到足够支持，或多个来源冲突而无法裁定。写明查过哪里、需补哪份记录及影响的判断，不据此指称作者造假。

同一根因原则上记一条主意见并列关联位置；同时涉及多个方面时选最能解释根因的一类，必要时附关联说明，避免重复计数。文风一般为次要；若实际缺证据、损坏主张或技术含义，按真实影响定级。仅有可疑文风不能成为学术不端或阻断判断；关键依据待核则可能是主要或阻断项，不能因为“待核”就一律降为次要。

按格式选择能稳定回查的锚点。Markdown、TXT 和 LaTeX 可用文件、标题或标签、行号。Word 可用章节、段落或表格单元格及原生批注锚点。PDF 可用页码加段落、图号与面板或表格行列。文字问题再附原文短引，分页会变化时同时给出对象位置。

仅审阅不改正文；确无问题可以给零项结果和实际覆盖范围。同时要求审阅件与润色件时，两者以同一原稿起步，每条意见对应“已改 / 保留并说明 / 待核”，再核干净稿确实落实。

## 校准实例（仅示意，不是可填入论文的研究事实）

- 原句“本文通过系统性的深入研究，具有十分重要的理论与实践意义”，上下文没有新增判断：标【AI味与文风｜空泛评价重复】；若删句不损失信息即可删除，不换成“赋能应用”。
- 原句“降低了 20%”，后文才定义与基线 B 比较：标【篇章与逻辑｜比较基准后置】；若原始材料确认，把 B 移到首次比较处，保留指标、条件和数值。
- 原句“多次现场验证表明可靠性提高”，只有仿真记录：标【依据待核｜现场验证记录缺失】；指出仿真材料位置并请补记录。不能仅作为“去 AI 味”改成“现场结果证实”。
- 原句“在负载 L 下，吞吐量由 100 增至 112 req/s”，数据支持且上下文基准明确：保留。不能为了去模板化而删掉工况，也不能把增加 12% 写成增加 12 个百分点。
- 英文方法句 “Each specimen was weighed three times.”：操作、次数和时态都清楚时保留，不为避免被动式改写。
- “未在数据集 D 上观察到显著差异”不得改成“方法在所有数据集上等效”；否定范围和统计结论同时变了。

## 最终版本的独立终检

起草、润色、仅审阅，以及给出零项结果时，都在交付前另读一次**最终版本**。修改过程中的扫描不替代终检。

1. **覆盖完整。** 片段任务读完指定片段与必要上下文；整稿从题名、双语摘要、正文到结论、参考文献和附录，并核实际存在的表头、单元格、图题图例、公式及说明、脚注和承载要求的页眉页脚。长稿内部记清已读 / 待核 / 不可读位置，不用抽样冒充全文通检。
2. **双向追溯。** 从原材料查到成稿，确认事实、条件、例外和归属没有遗失；再从成稿的主张、步骤、评价及每条意见回到原材料。对照标题—摘要—正文—图表—结论及中英版本，先统一对象、基线、单位和展示精度再判断冲突。
3. **复核含义保真。** 对照前述不可变项，逐项核数值归属、单位、不等号、上下标、否定和因果范围。可运行本技能的字面量核对工具辅助发现遗漏；工具计数相同仍不能证明含义相同。
4. **检查实际交付物。** 文本回读最终输出；文件保存后重新打开或回读并检查图表、公式、引用及批注锚点。交付 Word / PDF 等排版文件时，使用环境中适用的文档工具渲染检查关键版面；LaTeX 有编译条件时编译并核缺失引用、公式与版面。不能把提取成功等同于版面通过；原生批注须核选区、文字和实际条数。
5. **改后再核。** 有依据的问题按模式修正文或意见，回查所有关联位置；重存或重导出后再核受影响内容与衔接。完成最终通读才交付，不无限迭代偏好性改写。确实读不到时说明准确位置和受影响判断，只对已核部分下结论。

起草和润色默认交成稿，不把检查标签塞入正文。审阅交实质问题、范围和未决项；“未发现需修改的问题”仅适用于已读且核对完的范围。内部完成的检查不必全部写给用户。

## 字面量保真辅助工具

本技能的[字面量核对工具](../scripts/check_literals.py)借鉴 Unbot 对原文和成稿做保真复核的方法。发布版由本项目独立实现，仅需 Python 3.9+ 标准库。在原文与成稿的 UTF-8 文本副本所在目录运行。解释器和技能目录见[平台说明](platforms.md)。

```text
python "<技能目录>/scripts/check_literals.py" before.md after.md --keep "12 ms" --keep="--dry-run"
```

对选定润色片段可先导出同范围的改前、改后文本，不比较范围不同的整稿。工具比较数字与指定连续片段的出现次数，能提示数字正负号、不等号、百分号及部分 Unicode / HTML / TeX 数字上下标变化。常见等价排印（如 `<=`、`≤`、`\leqslant`，或负号 `-` 与 `−`）按同一数值符号计数。`--keep` 片段必须存在于原文；以 `-` 开头时使用 `--keep="片段"`。退出码 `0` 为所查计数一致，`1` 为有差异待复核，`2` 为参数或读取错误。

计数一致无法检出组值互换、数值归属、同数换单位、条件/否定删除或无数字公式的运算改变；关键公式、单位和限定可用 `--keep` 辅助，仍需语义回读。增删段落、正常修正与引用重编号也会造成合理差异，不能自动判错。Office 原生上下标可能在提取时丢失，须对照实际显示。此工具不做 AI 检测，不改原文，不联网。

## 长稿的轻量恢复记录

沿用项目已有记录，不要求固定目录或新增一套状态系统。每完成一节或一批意见，以及耗时导出或查证前，保存可恢复稿件、原稿身份/版本、本次范围、已覆盖位置、开放问题和下一步。继续时核对请求与原稿是否仍匹配；原文变动后重新定位受影响意见，不沿用失效行号或批注锚点。记录写“完成”不能代替实际成果，恢复后仍需对本次最终交付范围终检。
