# 长稿修订、复审与投稿交付

用于多轮修订、审稿回复、匿名稿与投稿材料。编辑权限与保真契约见[自然写作](natural-writing-and-review.md)，格式执行见[文档工作流](document-workflows.md)。短段润色不启动完整投稿流程。

## 一个版本，一份事实基础

在[项目记录](evidence-ledger.md)中保存当前稿件身份、适用规则来源、已确认决定、已读范围、关键主张的证据位置、开放问题与检查回执。可使用现有 Markdown 表；需要自动检查文件变化时再使用 JSON 记录。分别记“直接支持、条件支持、冲突、未查/未能取得”的含义，不能以文件完整或 DOI 可解析代替逐主张支持。

摘要、贡献段、表文、章小结和全文结论共享事实来源，语言可不同。改变一个数值、术语定义或核心条件，沿其使用位置复查图注、双语摘要、结果分析和回复。没有改动的区域保持原样；其他作者未委托处理的修订和批注不自行接受、拒绝或删除。

检查回执区分实际运行的脚本、模型语义复核、读取图像/页面和未检查。脚本发现无变化只对其覆盖范围有效；“核过的已登记主张占比”不能称“论文事实正确率”。未提供的附件、扫描页、表脚注或 Word 修订层分别记范围，不用正文提取代表全文件检查。

## 原文、意见和改稿相互可查

每条问题保存稳定 ID、稿件版本、短引或图表对象、根因、影响、证据和最小改法。实际回到原稿核对审阅者引用的话；找不到或属于旧版本时撤回/重新定位，不为了维护既有意见强行批评。复合意见拆成可核实动作，同一根因合并关联位置，保留原审稿编号与本次整理编号的区别。

修订记录至少能回答：原片段在哪里、改成什么、涉及表层/结构/主张哪类影响、为什么允许修改、关联位置是否同步。[修订台账](../templates/revision-ledger.md)可用于较长修改。用户只要干净稿时不强制附冗长台账，但未解决的事实冲突不能在后台选边后伪装已解决。

重新审阅时先看实际改稿、数据和差异，再看作者回复。沿用原评价依据，不因读到新稿无故抬高门槛；新增疑点写明是新改动引入还是先前遗漏。状态区分已解决、仍存在、回归、新发现和等待材料。只有对新版本完成了对应检查才关闭问题；仅换掉强词不能关闭缺证据问题。

## 回复审稿

逐条回复、学位论文修改说明、原稿—修改稿对照、覆盖核查及多轮承诺复核统一按[专用流程](reviewer-response-workflow.md)执行。下面是通用边界；具体表格与检查工具从该流程按需加载。仅有两个版本而无评审意见时，交真实修改对照，不杜撰专家编号和意见。

一条回复包含具体异议、作者立场、能支持立场的证据、实际修改或维持理由。已知立场沿用，未知立场不擅自全盘认错；存在有据分歧时明确澄清。语气克制不等于承认没发生的错误。

| 工作状态 | 回复处理 |
|---|---|
| 已完成且能定位改稿/运行/分析 | 使用完成时，给真实文件版本、章节/对象和必要结果 |
| 已明确决定但尚未完成 | 如实写计划；当年会议/期刊不允许追加内容时按规则处理 |
| 助手提出的可选建议 | 留在建议或待办中，不替作者承诺“我们将” |
| 信息不足或证据冲突 | 写具体缺口或条件化草稿，不编表号、统计检验、作者理由和实验结果 |

期刊回复通常逐点覆盖；会议 rebuttal 按实际限字、是否允许新实验/改稿和提交阶段组织，可以合并相同疑问但不遗漏独立异议。页码来自当前真实 PDF，同时给稳定的章节、图表或标签，不能沿用旧 `.aux` 或旧稿页码。未编译或未取得新 PDF 时只给稳定位置并注明页码待核。

统计回应先确认均值、SD、SE、CI 或配对差值分别属于谁；不能用候选方法自身 SD 来证明相对基线的差异显著。无法补实验时给真实原因与现有替代证据，不把建议的原因写成作者事实。处理审稿人技术问题，不推断其真实心态或计算无根据的提分概率。

## 匿名稿与多格式副本

按学校/刊物当年的匿名要求建立删除/保留清单，在新副本处理作者、机构、致谢、基金、个人成果、仓库链接、文件属性和图中身份信息；自引怎样表示也按该目标规定。记录来源与输出身份，核对原稿未变。不能从某个宏包的 blind 开关推断身份信息已经全部清除，也不能为匿名破坏必要引用或猜本人署名顺序。

同时交 DOCX 与 PDF 时，在工作副本完成需要的域/目录更新、保存并导出，核对实际同一版。仅导出 PDF 的委托可以保留原 DOCX，不能为了同步擅自保存源稿。LaTeX 工程需保留必要资源和可复建说明，检查输出新鲜性与未解决引文。原生可编辑对象、可编辑源、图片嵌入分别如实交代。

## 投稿材料包

使用[投稿检查单](../templates/submission-checklist.md)，只填适用于本次目标的材料：

- **投稿信：** 真实题名、主要贡献及与刊物范围的具体关系。原创性、未一稿多投、全体作者批准、利益冲突、伦理与数据许可是事实，不能由模板默认补齐。姓名、地址、编辑称谓未知时用清楚待填项。
- **Highlights 与图文摘要：** 每项给有据发现，保留比较条件。条数、词数/字符数以及是否含空格按实际稿约，不能把一个出版商的常用数字套到全部期刊。图文摘要文字对应实际图面，不描述未看到的图。
- **贡献、基金与数据声明：** 用真实分工映射目标要求的角色，不默认导师负责经费、学生负责软件；“未提供伦理材料”不等于“无需伦理审批”。数据与代码可用性需匹配真实发布位置和限制。
- **AI 使用说明：** 从本项目实际记录提取检索、起草、编辑、代码、分析和制图的用途与范围；按目标当前规则组织工具/版本及作者已完成的复核。不能将实质起草缩写成拼写检查，也不能替作者声称已全面复核。
- **推荐审稿人或申诉：** 仅在用户要求时处理，依据真实研究方向、公开信息和已知冲突；不能保证未公开关系不存在。不代发邮件或提交投稿。

目标期刊风格可以从实际取得的同类语料提炼引用融入、段落展开和图表写法；缺语料时采用中性学术表达并保留目标稿约，不假称“已经学习该刊风格”。换刊时重新核标题页、匿名状态、引用、篇幅、声明和附录要求，不能只改投稿信里的刊名。

## 草稿与终稿的区别

研究工作稿允许醒目待补项或附定位明确的缺口表；作者明确说研究未完成时保留该状态，不把未来结果写成“初步结果表明”。正式交付可同时给干净稿和问题单，但稿件中不能留下看似真实的占位引用/数据，更不能隐藏影响核心结论的缺口。最终声明只覆盖已完成的内容、结构和版面检查；达到预算或缺少外部材料时如实记录尚未完成的部分。
