# 实验设计

实验为主张服务。先写清主张和失败条件，再设计指标、基线、流程和记录口径。收到自行实验的委托后，按 [自主实验研究](computational-research.md) 完成环境试跑、实现、正式运行、分析与所要求的稿件。仿真器和数字逻辑设计按 [模型校验与 HDL 功能验证](simulation-and-hdl.md) 实施。以下检查按主张和任务选用。

通用模板见 [experiment-plan.md](../templates/experiment-plan.md) 与 [rq-matrix.md](../templates/rq-matrix.md)。通信仿真、消融和器件验证的步骤级规程在本文后半部分。器件刊物政策见 [venues-ieee-eds-cass.md](venues-ieee-eds-cass.md)。

## 设计步骤

1. 把每条主张改写成可检验的句子：在条件 C 下，相对于基线 B，方法 M 在指标 I 上应表现出……；若出现……则主张需改写或放弃。
2. 选择真正测量该主张的指标，不把代理指标（如缓存未命中）直接写成端到端性能或能耗，除非已经论证代理关系。
3. 选择基线：包含当代接近的方法，必要时加一个简单/随机基线；公平配置对手，不只和自己的上一篇比，不用过时基线夸大涨幅。
4. 规定数据、负载、信道、工艺或平台，以及训练/测试或校准/验证的分割，禁止用训练集或调参集冒充测试结果。
5. 规定重复次数、随机性处理、要报告的分布（方差、分位数或置信区间），而不是只报平均值。
6. 写下可复现所需的全部参数、版本、硬件/工具链。
7. 预先想好保守标准：目标场景上要有实质改进（进取标准），其他相关场景上应无严重回退，若有权衡就坦白分析（保守标准）。

**把问题落实为一行能运行的比较。** 写清每行代表哪个方法、工作负载、随机重复和测量阶段。相同轨迹上的方法使用相同外部输入。流量生成、搜索器、训练初始化和运行顺序使用各自的随机流。例如，多条流量轨迹可以衡量一个固定调度器随负载的变化，要比较遗传算法与随机搜索本身，还要重新运行两个搜索器；将同一训练出的策略在多个包上的表现计为多次训练会低估不确定性。测墙钟延迟时，同一机器同一时段形成一组，在组内交替或随机安排方法并记录次序。用预跑时间乘以实验单元数估计成本，把方案转成可执行的[实验矩阵](experiment-matrix.md)。[NIST 区组设计](https://www.itl.nist.gov/div898/handbook/pri/section3/pri332.htm) · [Bouthillier 等，MLSys 2021](https://proceedings.mlsys.org/paper_files/paper/2021/hash/0184b0cd3cfb185989f858a1d9f5c1eb-Abstract.html)

## 连续数值仿真

涉及步长、网格或迭代容差时，先用有解析解或独立高精度解的小问题检验实现。固定模型参数、初始条件、边界和终止时刻，只改变一个数值设置，在同一物理时刻或位置比较同一量。报告误差如何随细化变化、运行代价及论文关心的结论是否变号。若误差接近拟声称的改进，先细化或收窄结论。线性 RC 阶跃可用解析电压逐项核对积分器；校准器件模型仍需要独立测量。离散事件的同周期仲裁、RTL 的握手正确性分别用事件记录或事务断言校验。NASA 的方法原用于 CFD，这里借用解析基准与时空细化的判断。[NASA 数值验证方法](https://www.grc.nasa.gov/www/wind/valid/tutorial/verassess.html)

## 应用计算机 / 系统

吸收 SIGPLAN 经验评价清单与系统评测中常见问题，但按主张裁剪：

- **主张清楚且有范围：** 不要把子集结果写成“适用于全部某语言/全部负载”；不要把不真实的仿真写成“真实硬件上的结果”；有人工介入就不要写成全自动。
- **比较公平：** 对手要用合理配置；该用标准测试集时说明为何用或为何不用、为何子集。
- **数据与统计：** 非确定性系统要有足够次数；不同量纲或归一化分数慎用算术平均（常应考虑几何平均等，按数据性质选择）；报告分布。
- **呈现诚实：** 不要把 4%、6%、7% 和 49% 总结成“最高 49%”却暗示普遍如此；坐标轴不要误导。
- **常见评测错误（应避免）：** 只展示得意负载；用微基准冒充端到端；把吞吐下降 x% 说成“x% 开销”却用错分母；百分比与百分点混淆；平台信息不写；在嵌入相同假设的仿真器里“验证”自己的模型。

系统论文通常需要能表明问题被真正解决的评价。仿真不可避免时，必须为模型辩护，并避免声称已在真实硬件上证实。产物封装（可获取、可运行、可在容差内复现主要结论）对部分会议有加分，但不要把徽章写成学位论文的强制条件，除非学校或目标会议要求。即便对 ACM 期刊和会议，现行官方政策（Artifact Review and Badging Version 1.1；本轮打开的是 Wayback 捕获页，acm.org 源页本轮 HTTP 403）也写明这类评审 remain completely optional，作者参与也建议为可选。

Gernot Heiser 用确定性系统举例说明如何报告小幅重复测量波动。设计比较时，应分别考虑效应大小、估计的不确定度和工程上有意义的差值。若同一轨迹重放两种方法，先算每条轨迹的配对差，再按独立轨迹估计差异及其不确定度。两种方法各自的标准差可以很大，而差值仍能估得很精确。报告条件与分布，依主张选择重复方式。[Heiser 的系统评测说明](https://gernot-heiser.org/benchmarking-crimes.html) · [NIST 配对观测](https://www.itl.nist.gov/div898/handbook/prc/section3/prc311.htm)

## 通信

TCOM 一类刊物看重对读者有长久参考价值的理论或/和实验工作，政策页并不强制必须有硬件测量。分析、仿真与基线的信道/系统假设应一致，不一致要显式写出；基线须当代且公平调参；声称性能增益时讨论复杂度或开销；若主张包含实测或空口结果，必须真有测量，不能用仿真曲线冒充。

随机离散事件网络仿真的可信度规程，压缩自 Pawlikowski、Jeong、Lee，《On credibility of simulation studies of telecommunication networks》，*IEEE Communications Magazine*，2002（作者托管合法 PDF）。该文讨论的是电信网络随机仿真，**不是**误码计数的事件数规则，不得当成 BER 阈值的出处。

先区分测量目标。有限任务批、固定 trace 或以最后一包送达为终止事件的研究，应保存完整初始状态、释放过程、停止事件和末端排空，按工作负载或重复运行比较。初始等待也是该问题的一部分。对长期运行的稳态性能采用下列精度与暂态处理规程。[Law，仿真输出分析，第 3–4 节](https://www.informs-sim.org/wsc04papers/009.pdf)

- 正式运行前声明性能指标、目标区间半宽、置信水平和计算预算。均值或配对差可能接近零时，以原单位指定有实际意义的绝对精度。
- 可按独立预跑决定正式重复数，在固定预算结束时估计区间并报告达到的精度。若按精度序贯追加运行，采用与查看次数、停止规则及数据依赖结构相容的区间方法。连续查看固定样本量区间并在首次满意时停止会改变覆盖性质。[Kelton 与 Law，稳态仿真实验](https://pubsonline.informs.org/doi/abs/10.1287/opre.32.1.169) · [Howard 等，时间一致的置信序列](https://arxiv.org/abs/1810.08240)
- 稳态指标核查初始状态引起的暂态偏差，说明热身段的判定和处理。若使用批均值估计稳态波动，分别报告暂态处理与分批方式。不要发明「丢弃前 N 个包」一类默认条数。
- 用**独立重复**或另一种点名的置信区间方法（批均值、再生方法等），使区间在统计上有意义。一次任意加长、没有区间的运行不够。
- 使用经过检验的随机数发生器与独立流，避免不同方案因随意种子而意外相关；记录种子。
- **至少报告：** 性能估计、置信区间或相对误差、置信水平、暂态处理，以及足以重复的工作负载与模型细节。

**误码率 / 蒙特卡洛：** 可定性说明，估计的不确定度随观测到的错误事件增多而缩小；作者应报告观测窗口、观测到的错误个数，以及不确定性陈述。**不要写入任何具体的错误事件数或数值置信区间公式。** Jeruchim, “Techniques for Estimating the Bit Error Rate in the Simulation of Digital Communication Systems,” *IEEE JSAC* 2(1):153–170, 1984（DOI 10.1109/JSAC.1984.1146031）本轮仍未取得合法公开全文（IEEE stamp 未取得；GMU / MST 讲义仍未取得）。通信规程中**不写入数值 BER / 错误事件规则**。Hamkins，*Confidence Intervals for Error Rates Observed in Coded Communications Systems*，*The Interplanetary Network Progress Report* 42-201，2015-05-15，pp. 1–17（本轮打开的是官方 PDF 的 Wayback 原始字节，因 ipnpr.jpl.nasa.gov 直链 TLS 失败；该文用每码字误比特数的一、二阶样本矩）全文现已打开，但**不是** Jeruchim 的等价全文，不得用来写入默认错误事件数或数值置信区间公式，也不得填补 Jeruchim。Summerfield 1999 讲座仍不是 Jeruchim 的等价全文。对**编码或高阶调制**系统的 BER / CWER 区间：比特错误通常不独立，不要盲目套用假定比特独立的区间公式，应报告与相依结构相称的不确定度。不要把这一警告套到独立无编码二元信道上，以致禁止后者使用本来适用的独立事件方法。不要把文中 95% 口诀（4、16、400、4/w、4/γ² 等）写入技能默认。合法可用的网络仿真可信度规程仍是 **Pawlikowski、Jeong、Lee 2002**（序贯、基于覆盖率的停止，不用口诀式 N）；Hamkins 补充的是编码误码区间，不替代 Pawlikowski，也不改写其事先精度与序贯停止。若使用重要抽样等稀有事件方法，应点名并写清假设。

步骤级流程见下文「通信链路/网络仿真规程」。

## 半导体 / 电子

刊物政策（EDS touchstones、T-ED 现行 IFA 的 Adequate Validation、TCAS-II 硬性版式、特刊可能另行收紧）见 [venues-ieee-eds-cass.md](venues-ieee-eds-cass.md)。此处只保留设计层默认。T-ED IFA 已在 2026-11-11 于 https://eds.ieee.org/publications/transactions-on-electron-devices/information-for-authors 现行页复核（页内版权年 2025）；措辞保持「submissions should generally include at least partial direct physical validation of the results」，不要删「generally」，不要写成必须流片的全国规则，不要发明样本数或事件数。

- 主张类型决定证据类型：物理器件主张，按 T-ED 现行 IFA，**一般（generally）应包含至少部分直接物理验证**——副词是 generally，不是 always；该 IFA 并未写明纯方法类 TCAD 的例外。电路实现主张，TCAS 类默认规划对已实现电路的测量；TCAS-I/II 常设作者指南**并不禁止**纯仿真稿，特刊禁令仍只约束该特刊。仅方法的 TCAD/建模主张，仿真可以就是贡献，但必须把主张收窄到方法或模型，并写清校准与限度。
- 披露工具、全部关键参数、模型精度与工艺可行性依据。
- 禁止把未验证仿真写成芯片或器件的实测性能；正文里把**实测、经校准的仿真、预测性仿真**分开写。
- 样本数、重复测量和器件间变异：有则如实报告，**不要编造「必须测 N 只器件」**。片上射频或探针测量的温度、湿度、接触与重复结构等报告要求，见 [数据分析](data-analysis.md) 测量不确定度节；不要把那些条款套到所有直流 I–V 或电路仿真。若主张的是集成电路封装在静风箱中的结到环境热阻 θJA 比较，同一节另有 JESD51-2A 的环境报告要求：只适用于该标准的自然对流比较，不是预测应用结温，也不把 15°C–30°C 或 ±3°C 写成所有器件测量的默认。
- Ghione（T-ED, 2019）与 Sangiorgi（J-EDS）社论仍是具名、全文未取得的文献（合法 AAM 已知在 iris.polito.it，PDF 本轮被拦）。不要引用未见的例外，也不要把纯仿真投稿 T-ED 说成常规路径。

## 机器学习 / 数据驱动的应用研究

下列检查对应 NeurIPS 2022 及后续论文清单的轴，是报告义务，不是「必须 5 个种子 / 必须 p<0.05」的全国或全领域法令。清单并未把这些数字写成强制规则。Pineau 等，《Improving Reproducibility in Machine Learning Research (A Report from the NeurIPS 2019 Reproducibility Program)》，《JMLR》22(2021):1–20：清单提供的是稿件必须包含的最低信息，并不一定穷尽，更不是学位论文交稿门槛。不要把 NeurIPS「不交清单就 desk reject」、同期工作窗口或数据集发布日期写进学位论文规则；也不要把「没有 Limitations 专节」自动列为学位论文的主要缺陷。

1. **泄漏与划分：** 写清训练/验证/测试（或预训练/微调/测试）如何构造；预处理、特征选择、归一化、插补或增强是否只在训练集上拟合；公开基准若有官方划分，说明是否采用。分类粒度吸收 Kapoor 与 Narayanan，《Leakage and the reproducibility crisis in machine-learning-based science》，《Patterns》4, 100804，2023（主依据为 NSF PAR 刊登版；Cell 直链本轮 403）：无测试集；在全数据上做预处理、插补或特征选择；重复样本使同一样本同时出现在训练和测试中；使用对科学问题不合法的特征；测试集并非来自主张所针对的分布（含时间泄漏、训练—测试样本不独立、抽样偏差）。计算机应用中要点名检查被试、会话、器件、时间窗；通信或半导体测试数据尤其要防止同一器件、同一晶圆或同一时间段被拆进训练和测试后，再把结果写成对新器件或未来时段的性能。他们提议的模型信息表只作自查，不是学位论文或期刊强制附件。不要把该文在若干领域、若干篇论文中的计数，写成对用户题目的自动指控。纯系统设计或纯器件 I–V 题目，不必填写机器学习信息表。
2. **公平的超参预算：** 披露搜索空间、预算（试验次数、搜索方法或总计算量），以及基线是否得到**相当**的调参预算。不得在不说明的情况下，用精细调过的本文方法去比默认超参的基线。在公平预算之外，还要披露比较中实际随机化了什么；讨论差异时对照划分、种子、超参搜索等方差来源。依据 Dodge 等，《Show Your Work: Improved Reporting of Experimental Results》，arXiv:1909.03004（对应 EMNLP 2019；方法建议 / S），以及 Bouthillier 等，《Accounting for Variance in Machine Learning Benchmarks》，arXiv:2103.03098 / MLSys 2021（方法建议 / S）。不写死试验次数，不强制使用「期望验证性能」一类公式。
3. **测试集复用与顺序过拟合：** 选择在验证集上进行，测试集只用于最终评价。Lones，《How to avoid machine learning pitfalls: a guide for academic researchers》，arXiv:2108.02497v5（2024-08-29 更新；面向学术研究者的实践指南 / S，不是标准或会议强制清单）把「用同一测试集连续训练并比较多个模型或超参，并用测试表现指导下一次配置」称为 sequential overfitting（顺序过拟合），并指出它常常不被记录。若发生过反复窥视、在测试集上早停或做模型选择，必须报告。不要发明「最多看测试集几次」。
4. **多种子（及其他随机性）的均值：** 报告运行次数或随机种子、聚合方式（均值、标准差或另行声明的区间），以及随机化了什么（初始化、数据顺序、划分等）。当主张说的是典型性能时，单一种子的点估计不够。
5. **计算与环境：** 记录硬件、软件版本；主张依赖时，还记录训练时间或计算量。这是报告项，不是「必须使用某型号 GPU」。
6. **误差条与统计断言：** 若作出显著性陈述，点名检验方法和独立单元；不要把某个 p 阈值写成技能默认。统计报告原则见 [数据分析](data-analysis.md)。
7. **资产与限度：** 数据许可、代码可得性，以及已知的负面结果或失败情形（清单所问）。不要把「必须公开全部代码」写成学位条件，除非学校或目标刊物要求。

计算机应用技术中若只把机器学习当作部件（检测器、信道估计、良率模型等）：本小节约束该部件；通信或网络实验按稳态估计或终止型任务分流；器件主张另走物理验证。不要让公开基准上的消融，代替未经相应协议测量或仿真的通信/器件改进主张。

步骤级流程见下文「消融规程」。

## 与主张类型相称的评价（Empirical Standards 分册）

有限度吸收 ACM SIGSOFT Empirical Standards 分册原则（GitHub 活仓库 `acmsigsoft/EmpiricalStandards`，2026-11-11 取得 master；标 S，不是冻结出版页码）。总册「不要机械、僵硬、勾框或 gotcha」、未列出的属性不要临时当新标准，已在上轮编码，仍然适用。不要整份复制分册清单，不要把 Essential 当成学位论文法令，也不要把「必须公开全部代码」从可取（Desirable）升级为学位条件。

可吸收的原则：

- **与主张类型相称的评价。** 不要用一种评价菜单去套所有题目。
- **工程研究类**（提出并评价算法、模型、系统、工具等制品）：说清制品与评价方法，比较当代替代或说明为何无法比较。不要用该分册的评价菜单去否定纯理论证明，或否定 T-ED 政策已覆盖的器件验证方式。
- **数据驱动题目：** 报告预处理、基线，以及分布或变异，而不仅是单维汇总。与 [数据分析](data-analysis.md) 已有条款同向。
- **定量仿真。** 写明模型、工具与版本、校准、不同抽象层次的验证、每场景运行次数与终止或稳态条件。稳态估计还要交代精度、暂态处理、采用的固定预算或序贯停止方法。

**Experiments 分册只适用于有人类被试的受控或准实验**（操纵自变量并控制外来变量）。不能把该分册的样本量、随机分配或功效分析套到机器学习训练、器件 I–V 或网络仿真；无人类被试的实验应看 Data Science 或 Engineering Research 的原则，而不是把人类实验条款平移过来。不要把 Systematic Reviews 分册写成所有学位论文必须先做系统综述。

## 可运行规程（步骤级）

只收录能回溯到已取得来源的步骤，不写入无出处的实验室口诀（未注明来源的「一律扫 50 只器件」「一律 100 个错误」等）。Jeruchim 1984 与两份公开讲义仍未取得，通信规程中**不写入数值 BER / 错误事件规则**。

### 消融规程

来源：NeurIPS 2022 清单；SIGPLAN 经验评价清单与 Heiser（第1轮，不重复争论）；NIST/SEMATECH 手册 §5.2.1.2、§5.3.3；Melis、Dyer、Blunsom，ICLR 2018 / arXiv:1707.05589；Huang，arXiv:2610.00373v1（预印本 / S）。不用 Meyes 2019。

1. 用一句话写下要检验的**主张**（性能、资源、稳健性或机制）。
2. 列出论文声称对主张起作用的**因素**（模块、损失、特征、系统部件）。消融是有计划地去掉或替换这些因素，不是随机删层。若因素可能交互，不要把单因素去掉后的差值写成独立主效应：NIST/SEMATECH e-Handbook of Statistical Methods §5.2.1.2 指出，一次只变一个因子的做法（OFAT）不能反映因子交互；§5.3.3 写明，需要估计交互时，不能只用主效应或筛选设计应付。不要规定必须做满因子设计。须披露各变体是否在相当预算下重新调参；未重调则限制因果措辞。Melis、Dyer、Blunsom，《On the State of the Art of Evaluation in Neural Language Models》，ICLR 2018（本处打开 arXiv:1707.05589）表明，超参失控可使架构比较的结论翻转，未重调会把模块效应与「超参为完整模型而设」混淆起来。不要写死调参次数，也不要规定必须使用某种调参器。去掉模块后的性能差不能自动写成该模块造成了增益。Huang，《When Do Attention-Head Ablations Support Causal Claims?》，arXiv:2610.00373v1（2026-09-30 预印本 / S）把「一次切除不能自我证明因果」写在 GPT-2 / DistilGPT2 注意力头零化的设定上，不是贡献主张式消融的通论；可引用这一限度，不得把它的实验检查项写成通用强制步骤。消融表上的多重比较继续按 [数据分析](data-analysis.md) 中已有的 ASA / Simmons 披露原则处理，不指定默认校正。
3. 冻结**协议**：数据集或负载及官方划分；软硬件；本文方法以及每一条基线/消融变体的超参预算；随机种子与聚合；指标；若做统计检验，点名检验与独立单元。
4. 在该协议下运行完整模型/完整系统，以及每一个预定的消融变体。看到测试结果后再只给完整模型重新调参，不可。
5. 报告变体相对指标的**表**（多种子或多种负载上的均值与变异），某因素并不起作用也要如实写。
6. 系统论文再加 SIGPLAN/Heiser 的问题：负载是否有代表性；基线是真实系统还是被削弱的稻草人；开销是否计入；读者能否按正文重复比较。

### 通信链路 / 网络仿真规程

以下步骤针对稳态随机性能估计。有限时域或固定轨迹采用 [终止与排空、配对及守恒检验](simulation-and-hdl.md)，先说明从何种初始状态运行到什么事件，再选择适用的重复和不确定性分析。

来源：Pawlikowski 等 2002。不写入数值 BER / 错误事件规则；Jeruchim 1984 与 GMU / MST 讲义仍未取得。

1. 写清**场景**：拓扑或链路模型、业务或源模型、信道、所研究的协议栈层次，以及**性能指标**（吞吐、时延、丢失、误码等）。
2. 在生产运行之前声明目标半宽、置信水平、固定预算或序贯停止规则，并选定相容的区间估计方法。
3. 选用经过检验的随机数发生器与独立流，记录种子。
4. 用**试运行**估计方差并观察暂态。采用**点名的**热身/暂态删除方法。不要发明默认包数。
5. 按预定预算完成正式重复，或按预定序贯方法运行到精度目标或预算上限。用上述设计报告实际区间及其半宽。
6. 对蒙特卡洛误码或稀有事件指标，报告观测窗口和**观测到的错误事件数**，并给出不确定性陈述。**不要填入默认事件数。** 若对象是编码或高阶调制系统的 BER / CWER，还须注意比特错误通常不独立，不要盲目套用假定比特独立的区间公式（见上文「误码率 / 蒙特卡洛」段）。若使用重要抽样等稀有事件方法，点名并写清假设。
7. 报告足以重复的模型、参数和种子信息；精度未达标等失败情形一并写出。

### 器件 I–V / 验证规程

来源：EDS touchstones 与 T-ED 现行 IFA「generally … at least partial direct physical validation」（第 8 轮 2026-11-11 于 eds.ieee.org 现行页复核，页内版权年 2025）；不编造样本容量口诀，也不把未见的社论例外写进步骤。

1. 写清**主张类型**：新结构或工艺、新机制、紧凑模型、TCAD 方法，或使用该器件的电路。证据计划必须与主张相称。
2. 若主张关于**物理器件**，按 T-ED 现行 IFA **一般**规划**至少部分直接物理验证**（副词是 generally）。IFA 未写明纯方法类 TCAD 的例外；仅当主张明确收窄到方法或模型时，仿真才可以是贡献，且仍须说明校准与限度。
3. 规定**测量或仿真协议**：结构/工艺节点、偏置、温度、仪器或 TCAD 卡片、校准所依据的测量（如有）。做 I–V 时，写明将扫描什么（VGS、VDS 等）、将提取什么（阈值、亚阈值摆幅、开关比、跨导、击穿等）——这些是可测量项，不是每篇论文的强制清单。
4. 如实披露实际收集到的**样本与重复性**信息（器件或芯片数、片间或晶圆变异、回滞或扫描方向）。**不要发明必需的 N。**
5. 面向 TCAS 类刊物的电路实现主张，默认规划对**已实现电路的测量**。常设 IFA 并不全面禁止纯仿真；特刊若另有禁令，只约束该特刊。
6. 正文中把实测、经校准的仿真和预测性仿真分开，主张不越出证据类型。

## 与“再做一组实验”的边界

若现有实验已经在合理基线和指标上支撑所写主张，审查时不要把“还可以再做很多”当成必须修改的缺陷。只有当缺了某项实验会导致主张失去 warrant（例如声称端到端改进却只有微基准，或声称通用性却只有一个玩具数据）时，才列为主要或阻断问题。
