# ThesisForge 系统审计与修复（2026-11-18）

本文前半部分记录首轮系统审计；最终提交版本的追加修复与 250 项回归结果见[提交前追加复核](#提交前追加复核)及[提交前验证记录](precommit-validation.json)。历史验证文件不作为后续修改版本的验收。

本轮在已有未提交成果上进行直接修复，检查任务路由、写作边界、实验规程、证据记录、两稿与审稿回复核查、Word/LaTeX 工具及跨平台安装。保留自主实验能力，也保留局部润色的轻量入口；未提交 Git、推送仓库或替换用户级技能安装。

主要问题集中在版本身份、修订视图和静态工具的判断边界。修复后的工具更明确地区分“文件存在或文字匹配”“当前版本有实际修改”“学术问题已经解决”，后者仍需要内容判断。完整测试命令、跳过项和本轮运行资源指纹另存于 [验证记录](systematic-audit-validation.json)。此前两份 integration validation 文件保留为各阶段历史记录。

## 检查覆盖

| 功能 | 本轮检查 | 结论与范围 |
|---|---|---|
| 接入、研究、撰写、审阅与润色 | 主入口与专项规则交叉核对；独立调用实际润色与翻译 | 消除缺少材料时误删原结论的歧义；界面简介补齐审稿回复入口，默认提示按用户任务分流 |
| 选题、实验设计与数据分析 | 贡献—证据、固定/序贯样本、配对与独立重复、指标汇总规程 | 修正 BER 区间绝对禁令及统计单位表述；不承诺创新性或录用 |
| 环境、实验执行与续跑 | 环境探测、运行器、矩阵和配对分析回归；NoC 复跑；Icarus 探针 | 修复命令定位和旧缓存冒充新输出；未进行大规模训练 |
| 证据、两稿与逐条回复 | 版本变更、缺稿、来源变更、子问题覆盖、修订投影和文稿中途变动 | 无法确认的材料明确待核，登记覆盖不等于意见解决 |
| Word 与 LaTeX | OOXML 合成反例、源码静态检查、构建失败及超时测试 | 修复严格模式误报和旧 PDF 成功状态；未实际运行 TeX 排版 |
| 图表与自然表达 | 图稿物理尺寸检查回归、图形后端接口回归、保真字面量回归 | 保留最终尺寸与视觉验收要求；程序通过不替代实际读图 |
| 本地文献、安装与资源 | BibTeX/RIS/JSON 回归、双宿主隔离安装、资源链接和入口检查 | 未发现需要额外修改的确证缺陷；不等于文献内容已核实 |

| 推荐性标准被“底线”措辞暗示为所有学校硬规则 | 未规定事项作为参考，区分要求、建议和示例 | [学校叠加层](../references/school-overlays.md) |

| Word 删除行、单元格及段落标记修订被误作可靠正文 | 标明局部 `projection_ambiguities`，相关证据降为待核，普通段落不受影响 | [两稿提取](../scripts/compare_manuscripts.py) |
| 多文件审计期间早先稿件改变，结果仍称当前 | 生成报告前复核已读材料指纹；变化时停止并要求重跑 | [回复核查](../scripts/audit_reviewer_response.py) |
| 台账解析与哈希读取的不是同一份字节 | 从同一字节快照解析台账，保留结束时变动检查及严格 JSON 校验 | [回复核查](../scripts/audit_reviewer_response.py) |
| DOCX 内容读取与指纹计算分离 | 在内存中解析已经计算身份的同一 ZIP 字节快照 | [DOCX 审计](../scripts/audit_docx.py) |
| 修订层、兼容分支的断链或书签被当成最终稿确定问题/目标 | 标记视图依赖并提示复核；无歧义的正文断链仍可阻断 | [DOCX 审计](../scripts/audit_docx.py) |
| `\verb` 中的 `%` 吞掉后续真实引用，或注释中的 verbatim 标记遮蔽正文 | 顺序处理注释与逐字环境 | [稿件静态审计](../scripts/audit_manuscript.py) |
| 现代 LaTeX 命令/环境定义被静态扫描判成确定错误 | 识别动态定义上下文，不能确定的标签与引用问题列为复核 | [稿件静态审计](../scripts/audit_manuscript.py) |
| 文献后端更新后未再次排版，旧 PDF 仍标成功 | 例如 `--passes 1` 时改为 `REVIEW_NEEDED` | [LaTeX 构建](../scripts/build_latex.py) |
| Windows 超时清理的 `taskkill` 失败后未回收根进程 | 继续尝试结束本次根进程，记录清理范围和 `partial`/`failed` | [LaTeX 构建](../scripts/build_latex.py) |
| Windows 带点程序名省略 `.exe` 时定位失败 | 按 PATHEXT 继续查找可执行扩展名 | [实验运行器](../scripts/run_experiment.py) |
| 新建输出父目录链接到旧缓存即可登记旧结果 | 结束时复核输出完整解析路径，拒绝这种重定向 | [实验运行器](../scripts/run_experiment.py) |
| 因某次未取得全文而禁止所有 BER 数值置信区间 | 按样本独立性、固定/序贯停止规则选择区间方法，不设统一错误事件数 | [实验设计](../references/experiment-design.md) |
| 独立重复与配对共享轨迹可能被误认为冲突；几何平均误解 | 区分独立实验单位和组内配对；明确几何平均不能混合不同量纲 | [实验设计](../references/experiment-design.md) |

旧证据台账仍可读取，但来源证据没有 `observed_locator` 时不会沿用原“已支持”状态。应在实际回查来源后填写，不通过自动补齐字段冒充重新核实。远端 URL 的内容是否改变仍需实际阅读，工具不会联网认证。

独立调用使用新的执行者，只提供原任务与当前技能。任务是润色一段已完成实验的摘要，以及翻译指向另一篇文献的 `this paper`。实际输出保留了 12 条轨迹、每种方法 24 次评估、31.540/31.536 的数值归属、“未显示优于”的强度、测试范围和 `0≤x≤1`，翻译保留了另一篇论文与当前学位论文的区别。执行者明确只检查了文字保真，没有声称复验数据或运行实验。输入、输出和哈希保留在机器记录中；这是一例有边界的行为检查，不是模型准确率测评。

计算审计另在默认 WSL 的 Python 3.14.4 环境实际运行 `probe_environment.py --workspace . --workload hdl --verify iverilog`。Icarus Verilog/vvp 12.0 编译与仿真通过两个时钟边沿的已知答案校验。该环境与整套回归使用的 Ubuntu 24.04 分开记录，未安装新依赖。

## 保留的能力边界

- Word 修订投影不是完整排版引擎；复杂修订、图像文字、页行号及最终图表仍需实际渲染与目检。
- LaTeX 构建回归使用明确标注的合成引擎。本轮没有真实 TeX 排版或 Word COM 导出；历史验证记录中的运行不计成本轮运行。
- 通用实验运行器没有新增超时或派生进程树回收。按任务用实验自身/调度器设终止机制，中断后核实派生进程退出。构建器的清理能力不应被推及所有运行器。
- 文件指纹和结束复查不是文件锁；之后改稿、换数据或改脚本仍需重新核验。
- 未实际运行完整 AI 训练、商业 HDL 软件或两个宿主的真实对话；没有重新确认所有学校、期刊卡片的现行性。使用具体规范时仍核实际版本。
- 未改动第三方参考仓库快照、许可证，也未把开发报告加入安装负担。

## 提交前追加复核

再次独立检查后修正了四项具体问题：

1. `read_scope=unread` 不再支持题录身份主张；实际读过的元数据才能支持这一有限用途。
2. 删除来源与本地文件的绑定，不再使旧的失效主张恢复为已支持。冻结哈希无对应文件时标为待核。
3. LaTeX 首轮后发现 BibTeX/Biber 缺失时，统一返回 `TOOL_UNAVAILABLE / 2`，与缺依赖的文档契约一致，保留已有日志与部分产物供排查。
4. 反向文献检索限定在选题、自主研究或受托证据核查中，不因通用诚信规则扩大仅润色/翻译任务。

另外清理了一份新增开发记录的末尾空行，并按已有 `.gitattributes` 的 LF 规则统一 10 份开发/来源记录的换行，不改其数据或文字。本机仓库的 `core.filemode` 设为 `false`，排除 Windows 工作树的执行位噪声；该配置不进入发布包。
